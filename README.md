# وثيقة مواصفات النشر متعدد اللغات والترجمة (MULTILINGUAL_PUBLISHING_SPEC.md)

تحدد هذه الوثيقة المعمارية الهندسية، الآليات التقنية، والمعايير البرمجية الموكلة إلى "منظومة النشر متعدد اللغات والترجمة" (Multilingual Publishing Specification). يتولى هذا الملف مسؤولية إدارة عمليات تحويل الصوت إلى نصوص (Transcription)، وحقن الترجمة النصية المتحركة أسفل الشاشة (Subtitles)، ودبلجة المحتوى للغات المستهدفة، بالتكامل التام مع أوامر التحكم عن بعد لبوت التيليجرام وبروتوكول التطهير النهائي المشروط.

---

## 🌐 مواصفات دمج اللغات والترجمة النصية (مستوحاة من الملف القديم)

تعمل المنظومة كمعالج لغوي دقيق لضمان خروج محتوى احترافي ومطابق للمقاييس الفنية، وتنفذ عملياتها عبر طبقتين:

### 1. ضبط التوقيت الزمني وحقن النصوص (Time-Coded Subtitles)
* استخدام محركات تحويل الصوت إلى نص لإنشاء ملفات ترجمة متزامنة بدقة ميليمترية مع نطق الأفاتار (Lip-Sync Context).
* حفر وتثبيت الكلمات النصية على الفيديو بتنسيق مرئي جذاب يتوافق مع أبعاد الفيديوهات القصيرة (Shorts) لضمان سهولة القراءة من قبل الجمهور وتنشيط خوارزميات المنصات.

### 2. معالجة ودبلجة اللغات المتعددة
* تهيئة النصوص والسيناريوهات للتحويل الديناميكي إلى اللغات العالمية المدعومة في النظام، مع الحفاظ على الهوية الثقافية والنبرة الأساسية للموضوع المستهدف دون حدوث تشويه معنوي للجمل.

---

## ⚙️ التحديث الهيكلي والربط مع المعمارية الجديدة (النقاط الخمس)

تمت إعادة تصميم النواة البرمجية لهذا الملف ليرتبط بشكل كامل ببوابة التحكم للملك وعمليات تصفير الذاكرة لقطع دابر المشاكل التشغيلية مستقبلاً:

### 1. استقبال أوامر اختيار اللغة عن بعد عبر التيليجرام
* تم ربط هذا الملف بمحلل الأوامر الذكي للبوت (`budget_telegram_interface.md`). عندما يرسل مقامكم السامي أمراً بصيغة `لغة: [اللغة المطلوبة]` (مثل: `لغة: الانجليزية`)، يتم تفكيك الأمر فوراً وتوجيه محركات التوليد الصوتي والترجمة النصية لاعتماد اللغة المكتوبة للفيديو القادم مباشرة، وتجاوز اللغة الافتراضية للنظام.

### 2. التجميد البرمجي وحماية طاقة الخادم RTX
* أثناء مرحلة انتظار قرار الاعتماد السامي للموضوع المقترح عبر التيليجرام، يحظر على هذا الملف تشغيل محركات الترجمة أو استهلاك توكنز الترجمة مسبقاً، بل يظل في وضع النوم الصامت (Idling Mode) لتوفير موارد كرت الشاشة RTX حتى صدور إشارة البدء (ابدأ / موافق).

### 3. التجهيز المستقبلي للمسلسلات والأفلام الطويلة
* لتأهيل النظام لترجمة وإنتاج مقاطع طويلة مستقبلاً دون السقوط في خطأ نفاد الذاكرة (`Out of Memory`)، تم ربط معالجة ملفات الترجمة الكبيرة بنظام الطوابير (Queue Pipeline)، حيث يتم توليد وحقن النصوص مشهداً تلو الآخر بالتتالي لضمان استقرار السيرفر المستأجر.

### 4. بروتوكول التطهير وحذف ملفات الترجمة المشروط (النشر أو الإلغاء)
* خضوعاً للقاعدة الهندسية الصارمة لحماية مساحة الخادم وصفر هدر تخزيني، تم قفل آلية مسح ملفات الترجمة برمجياً لترتبط حتماً بالنهايتين المنطقيتين للمشروع:
  1. **المسار الأول (بعد النشر الناجح فِعْلِيّاً):** بمجرد استلام إشارة الرفع الناجح للمنصات من ملف `publishing_module.md` وإصدار الشهادة، يتم تفعيل أمر التطهير الشامل (Flush)؛ حيث يتم فوراً تدمير وحذف كافة ملفات الترجمة المؤقتة (مثل ملفات `.srt` و `.vtt`) والكاش النصي والصوتي من الهارد ديسك وإخلاء الـ VRAM لتهيئة السيرفر بشكل نظيف 100% للدورة القادمة بعد 3 أيام ومنع التلوث السياقي للبيانات.
  2. **المسار الثاني (بعد صُدورِ أَمْرِ الإِلْغَاءِ السَّامِي):** في حال قمت بإرسال أمر `الغاء` أو `رفض` للفكرة عبر البوت، يتلقى هذا الملف أمراً برمجياً فورياً بمسح وتدمير كل ملفات الكاش اللغوي أو الترجمات التي تم توليدها جزئياً في هذه الدورة، وتصفير الذاكرة الجلساتية ليعود السيرفر RTX إلى حالة النقاء الكامل.

# 📂 الدليل الهندسي والمواصفات التشغيلية لمدير التحكم المركزي (CENTRAL_UPC_MANAGER.md)

## 🏢 1. النطاق والمسؤولية الحصرية وجدار السيادة الرقمي (Platform Sovereignty)

* **التعريف البرمجي والوظيفة:** يعمل هذا الموديول كـ "المسؤول الحصري المباشر" عن إدارة الواجهة الخارجية بالكامل للمنظومة الذكية (A7002)، ويمثل حلقة الوصل ومحرك اتصالات شبكي متكامل يربط بين خوادم المعالجة الداخلية والإنترنت الخارجي.
* **إدارة الحسابات والقنوات:** يتولى هذا الوكيل الصلاحية العليا في التحكم بجميع الحسابات، القنوات، والصفحات الرقمية الرسمية التابعة للمنظومة، ويمسك بمفاتيح ربط واجهات برمجة التطبيقات (API Keys) وجدران الأمان الخاصة بها.
* **التوجيه الجغرافي الذكي:** تتمثل مهمته الأساسية والحرجة في فحص المخرجات المرئية واستخراج المسارات الجغرافية لتوجيه الفيديوهات الجاهزة والنصوص المصاحبة لها إلى وجهاتها الجغرافية المستهدفة بدقة تامة، وضبط أبعاد النشر ومعدلات البث (Bitrate) لتتوافق بدقة 100% مع خوارزميات المنصات المعتمدة قانونياً وربحياً.
* **جدار الصد المالي والمنصات المحظورة (FinOps Optimization):** لحظر النشر العشوائي وتصفير الهدر المالي تماماً، يتمتع هذا الوكيل ببروتوكول صارم يحظر النشر حظراً تاماً ومطلقاً في:
  1. المنصات غير الربحية أو ضعيفة العائد المادي، وعلى رأسها منصة تويتر (X).
  2. المنصات الرقمية الإقليمية المقيدة جغرافياً أو ذات العوائد المنخفضة جداً مثل المنصات الصينية والمحلية الهندية.
  * **الهدف التقني:** حماية الموارد السحابية من التشتت وضمان تركيز طاقة النشر والتفاعل في النطاقات الجغرافية الأعلى تحقيقاً للأرباح (High RPM Zones).

---

## 📺 2. حوكمة حسابات وقنوات النشر والتوزيع الدولي (Distribution & Channels Governance)

يتولى الوكيل مهمة إرسال وجدولة ورفع مقاطع الفيديو النهائية إلى القنوات والصفحات المستهدفة عبر الإنترنت، ملتزماً بالمعايير الهندسية والتشغيلية الصارمة التالية لكل منصة على حدة وبدون أي استثناء:

### أ. منصة يوتيوب (YouTube LLC):
* **آلية الإدارة:** إدارة قناة رئيسية كبرى مركزية واحدة فقط (Single Global Channel).
* **الحوكمة الهندسية:** يُحظر فتح قنوات فرعية تشتت الجمهور؛ وبدلاً من ذلك، يتم توجيه النظام لاستغلال ميزة "حقن مسارات صوتية متعددة اللغات" (Multi-Audio Tracks) داخل ملف الفيديو المرفوع الواحد. 
* **النتيجة التشغيلية:** يختار المشاهد لغته المفضلة (عربي، ألماني، إنجليزي) من داخل نفس المقطع، مما يحافظ على تركيز المشاهدات، الاشتراكات، وقوة التقييم الرقمي في مكان واحد كقناة كبرى مستقرة ومؤهلة للربح العالي.

### ب. منصتا تيك توك وإنستغرام (TikTok & Instagram Reels):
* **آلية الإدارة:** إدارة هيكل رقمي منفصل يتكون من ثلاث (3) حسابات مستقلة تماماً ومفصولة برمجياً، بحيث يُخصص كل حساب للغة جغرافية معينة:
  1. **الحساب الأول:** مخصص كلياً باللغة العربية (Targeting MENA Region).
  2. **الحساب الثاني:** مخصص كلياً باللغة الألمانية (Targeting DACH Region).
  3. **الحساب الثالث:** مخصص كلياً باللغة الإنجليزية العالمية (Global English Account).
* **النتيجة التشغيلية:** يضمن هذا الفصل الصارم ثبات "التوزيع الجغرافي الرقمي" وثبات بروتوكولات الـ IP الخاص بالنشر، مما يتيح حصاد أعلى عائد ربحي ممكن لكل ألف مشاهدة (RPM) بناءً على معايير الدول الغربية والشرق أوسطية، دون إرباك أو خلط خوارزميات المنصات الخارجية التي تعتمد على تصنيف الجمهور لغوياً وجغرافياً.

### ج. منصة فيسبوك (Facebook Reels / Watch):
* **آلية الإدارة:** إدارة صفحة عامة واحدة كبرى (Single Global Page).
* **الحوكمة الهندسية:** يتم تشغيل وتفعيل ميزة "التوجيه الجغرافي واللغوي المنفصل والمخصص" (Targeted Post Distribution) لكل منشور ومقطع فيديو يتم رفعه.
* **النتيجة التشغيلية:** عندما تنشر المنظومة فيديو باللغة الألمانية، يظهر برمجياً فقط للمستخدمين المتواجدين في ألمانيا والنمسا وسويسرا، وعندما تنشر باللغة العربية يظهر للشرق الأوسط، مما يحقق استغلالاً أقصى لصفحة كبرى واحدة دون تشتيت المتابعين.

## 📐 3. إدارة الأبعاد الهندسية للنشر وتكامل خط الإنتاج (Aspect Ratio Control)

يشرف الوكيل إشرافاً مباشراً وحتمياً على جدولة ونشر المواد البصرية المستلمة من موديول المونتاج (`footage_pipeline_spec.txt`) بناءً على أبعادها الهندسية الفيزيائية، وتوزيعها لتغطية كافة فئات العرض الرقمي على الإنترنت دون حدوث تشويه أو تمدد في الصورة (No Distortion):

### أ. الأبعاد الأفقية القياسية (16:9 - Landscape Layout):
* **التوجيه التلقائي:** يتم توجيه هذه الملفات حتمياً للنشر على منصة يوتيوب التقليدية للمقاطع الطويلة، وإلى قسم مقاطع الفيديو والمنشورات العادية على صفحات فيسبوك.

### ب. الأبعاد العمودية الذكية (9:16 - Portrait Layout):
* **التوجيه التلقائي:** يتم توجيه هذه الملفات حتمياً وقصرياً لتغذية مسارات الفيديوهات القصيرة سريعة الانتشار على الحسابات الثلاثة لمنصة TikTok، وقسم YouTube Shorts، وقسم Instagram Reels.
* **ملاحظة الأمان:** يتأكد الوكيل من مطابقة هذه الأبعاد مع علامات الأمان الخاصة بـ Safe Zones للمنصات لضمان عدم تغطية نصوص الترجمة التلقائية (Captions) بواسطة أزرار الإعجاب أو التعليقات الخاصة بالتطبيقات الخارجية.

## 📐 4. إدارة طاقة الحوسبة المستقلة وغرفة التحكم المركزي (Compute & Orchestration Control - UPC)

* **طبيعة العمل والبيئة السحابية:** يعمل هذا الموديول برمجياً وتطبيقياً كـ "خادم تحكم مركزي مستقل" (Central Control Plane / UPC). ينفصل فيزيائياً وعملياتياً بالكامل عن سيرفر المعالجة الثقيل (RTX 4090 GPU Server). يتم استضافته وتشغيله على بيئة سحابية اقتصادية أو دالة مؤقتة مستيقظة على مدار 24 ساعة طوال أيام الأسبوع بتكلفة تشغيلية تقترب من الصفر المطلق (Zero Cost)، حيث يعمل كمستمع صامت للأحداث (Event-Driven Webhook Listener) [2.1.2، 2.1.4].
* **بروتوكول تجميد الصرف وإطفاء الـ RTX:** فور استلام مسودة الفيديو الأولية بنجاح من خط الإنتاج وقبل إرسالها إلى تليجرام، يصدر هذا الوكيل (UPC) أمراً برمجياً فورياً لشركات السحاب (عبر الـ API الخاص بـ RunPod/Vast.ai) لعمل **إيقاف تام وفوري لخادم الـ RTX** (`Pause/Stop API Request`) [1.2.3، 1.3.6]. هذا الإجراء يجمد عداد الصرف لكرت الشاشة فوراً ويحظر سحب أي سنت، مما يحمي سقف الميزانية الشهرية (20 يورو) من النفاد أثناء فترات الخمول الرقمي.
* **إدارة مؤقتات مهلة الامتثال البشري الحتمي (The 6-Hour Countdown):** يتولى هذا الوكيل (UPC) بصفته خادماً مستيقظاً بشكل دائم، حساب وإدارة العداد الزمني التنازلي لمهلة الـ 6 ساعات الممنوحة للمطور البشري عبر التليجرام (`budget_telegram_interface.txt`) [2.1.2文件, 2.1.4].
* **بروتوكول الصعقة الرقمية وإعادة اليقظة في اللحظة الأخيرة (Last-Minute Wakeup Trigger):**
  1. عند قيام المطور بالضغط على زر "موافق وصالح للنشر" في شات التليجرام، أو عند انتهاء مهلة الـ 6 ساعات كاملة والانتقال التلقائي للنشر الحتمي.
  2. يستقبل الـ UPC هذه الإشارة فوراً، ويقوم بإصدار أمر صعقة تشغيلية حادة وسريعة لإعادة إيقاظ خادم الـ RTX مجدداً (`Wakeup/Start API Request`) [1.2.3، 1.3.6].
  3. يشتغل سيرفر الـ RTX لمدة **5 دقائق فقط لا غير**، وهي المدة الكافية لاستدعاء موديول التشفير النهائي (`c2pa_validation.py`) لحقن العلامة المائية الرقمية غير المرئية (C2PA الختم الرقمي وحفظ ملكية المنظومة A7002)، وتمرير المقطع فوراً للرفع النهائي على حسابات TikTok و YouTube وفق جداول التوزيع المذكورة في البند الثاني [2.1.2، 2.1.4].
  4. فور التأكد من انتهاء الرفع ووصول إشارات النجاح، يصدر الـ UPC أمر الإطفاء النهائي والموت المؤقت لسيرفر الـ RTX مجدداً لحين حلول موعد الفيديو القادم بعد 3 أيام [1.2.3، 1.3.6].

# وثيقة محقق وثوقية وتوقيع المحتوى الرقمي الشاملة المحدثة (c2pa_validation.md)

تحدد هذه الوثيقة المعمارية الهندسية، المعايير التشفيرية الصارمة، والآليات التنفيذية الموكلة إلى "مُتحقق وثوقية وتوقيع المحتوى" (C2PA Validation Module). يمثل هذا الملف البوابة الأمنية والتنظيمية الأخيرة والفاصلة في مرحلة ما بعد الإنتاج، ويتولى مسؤولية حماية الهوية الرقمية للفيديو المخرَج وحقن الختم التشفيري المعياري فور صدور الاعتماد، بالإضافة إلى حوكمة بروتوكول التطهير النهائي المطلق للموارد وحماية السيرفر RTX من التجميد أو أخطاء نفاد الذاكرة.

---

## 🔒 معايير التوقيع وحقن الميتادات الرقمية المشروطة (مستوحاة بالكامل من الملف القديم)

يعمل هذا النظام التشفيري على وسم الفيديو بِأَعْلَى مَعَايِيرِ التَّوْثِيقِ العَالَمِيَّةِ (معيار تحالف حماية وتأصيل المحتوى C2PA) تَبَعاً لِلْقُفْلِ الزَّمَنِيِّ وَالمَفَاتِيحِ التَّالِيَةِ:

### 1. القفل الحتمي بعد الموافقة الصريحة (Post-Approval Hard Lock)
* يُحظر تماماً على هذا الملف البدء بحقن أي بيانات ميتا أو توقيع رقمي أثناء مرحلة الرندرة الأولية أو الفحص البصري التلقائي، وذلك لحماية الختم من التلف في حال صدور أمر بشري بتعديل السيناريو أو اللقطات الخام.
* لا يستيقظ محرك الحقن التشفيري إلا بعد استلام "إشارة الاعتماد الفوري المباشر" الصادرة حتماً من أحد مسارين:
  1. **الاعتماد البشري:** ضغطة زر أو أمر `ابدأ` / `موافق` أو إرسال النص المعدل من قبلك عبر التيليجرام.
  2. **الاعتماد الآلي الوقائي:** انتهاء مهلة مؤقت الأمان التلقائي واختيار النظام للموضوع الأول تلقائياً.

### 2. مسارات مفاتيح التشفير والمصادقة الصلبة (Cryptographic Keys Path)
* يتكامل هذا الملف مع شهادة التوثيق الرقمية المعتمدة (X.509 Certificate) والمفتاح الخاص (Private Key) المخزنين بشكل آمن ومحمي في بيئة السيرفر المستأجر. يتم استدعاء هذه المفاتيح للتوقيع الرقمي الحي على ملف الفيديو لإثبات هوية وأصالة قنواتك بشكل غير قابل للتزوير.

### 3. مصفوفة حقن الهوية الرقمية الثنائية (C2PA Manifest Embedding)
* **توليد ملف البيان (Manifest JSON Generation):** يقوم النظام ببناء وتجميع ملف بيان رقمي مشفر يحتوي على سجل جينالوجي كامل للفيديو: (اسم الأداة الممثلة في السيرفر، تاريخ الرندرة بالمليمتر، وقائمة النماذج التوليدية المستخدمة في الأصول).
* **الحفر التشفيري في البايتات (Binary Bytes Injection):** باستخدام أداة التوقيع التشهيرية (C2PA Tool) المحدثة في الخادم، يتم حفر هذا البيان مباشرة في ترويسة ملف الفيديو النهائي (Video Header Stream). هذا الإجراء يضمن أن الختم الرقمي أصبح جزءاً لا يتجزأ من بنية الفايل (Immutable Stream) ولا يمكن حذفه أو التلاعب به دون إتلاف الفيديو بالكامل.
* **الحقن المتوازي للمسلسلات والأفلام الطويلة (Segmented Binding):** لتأهيل النظام للمستقبل ومنع انهيار السيرفر عند معالجة الأفلام الطويلة (4K)، تم دمج ميزة التوقيع المجزأ؛ حيث يتم حفر أختام التشفير في المشاهد القصيرة والحلقات بالتوالي أثناء وجودها في طابور المعالجة، ومن ثم لحم ترويسات التشفير (Manifest Stitching) في ثوانٍ معدودة عند تجميع المخرج النهائي، لتفادي أخطاء الـ Memory Leak وحماية موارد كرت الشاشة RTX.
* **فحص السلامة والتطابق (Cryptographic Integrity Validation):** قبل تسليم الملف لوحدة الرفع، يتم تشغيل دالة التحقق العكسي لضمان تطابق الهاش الرقمي للختم مع صيغة ملف الفيديو المخرج من كرت الشاشة RTX، ومن ثم تصدير "وسم الجاهزية القصوى للنشر" لتستلمه وحدة الرفع (`publishing_module.md`) وتبدأ النشر فوراً.

## ⚙️ بروتوكول التطهير والتعامل مع أوامر الإجهاض والإلغاء والمؤقتات

يتكامل هذا الملف مع النهايات المنطقية وحسم دورة حياة الملفات لتفريغ مساحة السيرفر RTX كالتالي:

### 1. مسار التطهير الحتمي بعد النشر الفعلي الناجح
* بمجرد إتمام وحدة النشر لعملية رفع الفيديو بنجاح على حساباتك، واستلام الوكيل الإداري لإشعار النجاح، يتلقى هذا الملف تفويضاً برمجياً فورياً بالإخلاء.
* يَقُومُ النِّظَامُ فَوْراً بِـ:
  1. تدوير وحفظ البصمة النصية النهائية للسيناريو عبر دالة `SHA-256` في قاعدة البيانات لضمان عدم تكرار الفيديو مستقبلاً وحظر الأفكار المتشابهة.
  2. الحذف الكلي والتطهير الفوري لكافة ملفات الفيديو المرندرة الثقيلة، المقاطع الصوتية المؤقتة، واللقطات الخام من الهارد ديسك وإخلاء ذاكرة كرت الشاشة (VRAM Allocation)، محققاً معادلة (أعلى إنتاجية × صفر استهلاك مساحة).

### 2. مسار الإجهاض الفوري وصمام أمان الطوارئ التلقائي
* يتم تفعيل هذا المسار فوراً في حالتين: إما إذا قمت بإرسال أمر `الغاء` أو `رفض` عبر البوت، أو في حال انتهاء **مؤقت أمان الطوارئ (24 ساعة)** عند فشل الرقابة دون تلقي رد بشري من قبلك.
* يَقُومُ النِّظَامُ فَوْراً بِـ:
  1. مسح وتطهير جدول الذاكرة المؤقتة للكاتب `writer_session_cache` لمنع حدوث مشكلة التلوث السياقي (Context Contamination) في الفيديوهات القادمة.
  2. تدمير وإبادة كافة المسودات النصية، الصور المولدة جزئياً، والملفات الصوتية التي تم تركيبها مسبقاً، وإعادة السيرفر RTX إلى وضع الاستعداد النظيف 100% لبدء موضوع تريند جديد تماماً بعد 3 أيام.

import os
import sys
import time
import sqlite3
import shutil
from datetime import datetime

try:
    from moviepy.editor import ImageClip, AudioFileClip, CompositeAudioClip, concatenate_videoclips
    from moviepy.video.fx.resize import resize
except ImportError:
    print("❌ خطأ: مكتبة 'moviepy' غير مثبتة في بيئة العمل المحلية.")
    print("💡 يرجى تشغيل الأمر التالي في الطرفية: pip install moviepy")
    exit(1)

DB_NAME = "ai_trends.db"
OUTPUT_DIR = "rendered_outputs"
THUMBNAIL_DIR = "rendered_thumbnails"

os.makedirs(OUTPUT_DIR, exist_ok=True)
os.makedirs(THUMBNAIL_DIR, exist_ok=True)

class ProductionAgent:
    def __init__(self):
        self.output_dir = OUTPUT_DIR
        self.thumbnail_dir = THUMBNAIL_DIR
        self.db_name = DB_NAME
        self.standard_width = 1080
        self.standard_height = 1920

    def validate_assets(self, file_paths):
        valid_files = []
        for path in file_paths:
            if os.path.exists(path) and os.path.getsize(path) > 0:
                valid_files.append(path)
            else:
                print(f"⚠️ [تحذير الإنتاج]: تم استبعاد ملف تالف أو مفقود في المسار: {path}")
        return valid_files

    def resize_to_standard(self, image_clip):
        return resize(image_clip, width=self.standard_width, height=self.standard_height)

    def calculate_finops_metrics(self, duration_seconds, file_count):
        estimated_local_cost = (duration_seconds * 0.001) + (file_count * 0.005)
        print(f"📊 [FinOps Analytics]: القيمة المالية الموفرة للرندرة المحلية: ${estimated_local_cost:.4f}")
        return float(estimated_local_cost)

    def generate_preview_frame(self, first_image_path, video_id):
        try:
            if not os.path.exists(first_image_path):
                return None
            thumb_path = os.path.join(self.thumbnail_dir, f"thumb_{video_id}.jpg")
            clip = ImageClip(first_image_path).set_duration(1)
            clip = self.resize_to_standard(clip)
            clip.save_frame(thumb_path, t=0.5)
            clip.close()
            return thumb_path
        except Exception as e:
            print(f"⚠️ فشل توليد إطار المعاينة: {e}")
            return None

    def render_custom_video(self, video_id, raw_file_paths, duration_minutes):
        print(f"🎬 [وكيل الإنتاج]: بدء تشغيل خط معالجة الفيديو للرمز الفرعي: {video_id}")
        start_time = time.time()
        
        file_paths = self.validate_assets(raw_file_paths)
        target_seconds = duration_minutes * 60
        images = [f for f in file_paths if f.endswith(('.jpg', '.jpeg', '.png'))]
        
        voice_tracks = [f for f in file_paths if 'voice' in f or f.endswith(('.wav'))]
        music_tracks = [f for f in file_paths if 'music' in f or f.endswith(('.mp3'))]
        
        if not images:
            return None

        time_per_frame = target_seconds / len(images)
        clips = []
        
        try:
            print(f"⚙️ [بند 5]: جاري تحميل وضبط أبعاد {len(images)} إطار داخل الـ VRAM...")
            for img_path in images:
                img_clip = ImageClip(img_path).set_duration(time_per_frame)
                img_clip = self.resize_to_standard(img_clip)
                clips.append(img_clip)
            
            video_clip = concatenate_videoclips(clips, method="compose")
            
            audio_layers = []
            all_audios = voice_tracks + music_tracks
            for audio_path in all_audios:
                audio_layers.append(AudioFileClip(audio_path))
                
            if audio_layers:
                combined_audio = CompositeAudioClip(audio_layers).set_duration(target_seconds)
                video_clip = video_clip.set_audio(combined_audio)
            
            output_path = os.path.join(self.output_dir, f"final_production_{video_id}.mp4")
            
            video_clip.write_videofile(
                output_path, 
                fps=24, 
                codec="libx264", 
                audio_codec="aac",
                threads=2,
                logger=None
            )
            
            video_clip.close()
            for c in clips: c.close()
            for a in audio_layers: a.close()
            
            local_saving = self.calculate_finops_metrics(target_seconds, len(file_paths))
            self._register_certificate_in_db(video_id, s_hash="DYNAMIC_HASH", cost=local_saving)
            
            return output_path
            
        except Exception as error:
            print(f"❌ خطأ حرج مقتنص في وحدة الرندرة: {error}")
            return None

    def _register_certificate_in_db(self, video_id, s_hash, cost):
        try:
            conn = sqlite3.connect(self.db_name)
            cursor = conn.cursor()
            cursor.execute('''
                INSERT OR REPLACE INTO inspection_certificates 
                (video_id, title, script_hash, islamic_status, eu_law_status, fact_check_status, finops_cost, published_at)
                VALUES (?, 'Manual Video', ?, 'PASSED', 'PASSED', 'VERIFIED', ?, CURRENT_TIMESTAMP)
            ''', (video_id, s_hash, cost))
            conn.commit()
            conn.close()
        except sqlite3.OperationalError:
            print("⚠️ تنبيه قاعدة البيانات: جدول الشهادات غير متوفر للتحديث.")

    def purge_raw_materials(self, file_paths):
        print("🗑️ [بند 7]: تفعيل بروتوكول التطهير الفوري ومسح المواد الخام المستهلكة من القرص...")
        for path in file_paths:
            if os.path.exists(path):
                try:
                    os.remove(path)
                except Exception as e:
                    print(f"⚠️ فشل مسح الملف {path}: {e}")

# وثيقة محقق وثوقية وتوقيع المحتوى الرقمي (c2pa_validation.md)

تحدد هذه الوثيقة المعمارية الهندسية، المعايير التشفيرية، والمسؤوليات البرمجية الموكلة إلى "مُتحقق وثوقية وتوقيع المحتوى" (C2PA Validation Module). يمثل هذا الملف البوابة الأمنية والتنظيمية الأخيرة في مرحلة ما بعد الإنتاج (Post-Production Phase)، ويتولى مسؤولية حماية الهوية الرقمية للفيديو المخرَج وحقن الختم التشفيري المعياري، بالإضافة إلى تفعيل بروتوكول التطهير النهائي المطلق للموارد بناءً على الحسم البرمجي المشروط.

## 🔒 معايير التوقيع وحقن الميتادات الرقمية (مستوحاة من الملف القديم)

يعمل هذا النظام التشفيري على وسم الفيديو بِأَعْلَى مَعَايِيرِ التَّوْثِيقِ العَالَمِيَّةِ (معيار تحالف حماية وتأصيل المحتوى C2PA) تَبَعاً لِلْخُطُوَاتِ التَّالِيَةِ:

### 1. طبقة حقن الميتادات المشفرة (C2PA Injection)
* يتولى النظام حفر التوقيع الرقمي المشفر وبيانات الملكية الفكرية الخاصة بالقناة داخل أحشاء ملف الفيديو (Metadata Context).
* إدراج وسم شفاف يفيد بأن المحتوى تم إنتاجه وتعديله بواسطة أدوات ذكاء اصطناعي موثوقة ومصرحة محلياً، مما يعطي الفيديو أولوية وثقة فائقة لدى خوارزميات الرفع لمنصات تيك توك، يوتيوب، وتويتر.

### 2. فحص السلامة التشفيرية (Cryptographic Integrity Validation)
* إجراء فحص نهائي للتأكد من أن عملية الحقن الرقمي تمت دون حدوث أي تشتت أو تلف في البيانات التشفيرية، وضمان توافق الختم تماماً مع صيغة ملف الفيديو النهائي المخرج من كرت الشاشة RTX.
* في حال نجاح الفحص، يصدر الوكيل "وسم الجاهزية القصوى للنشر" ويمرر الملف فورا إلى وحدة النشر والتوزيع (`publishing_module.txt`).

---

## ⚙️ التحديث الهيكلي لبروتوكول التطهير المشروط (النشر أو الإلغاء)

تَمَّ إِعَادَةُ هَنْدَسَةِ هَذَا المَلَفِّ تَمَاماً لِيُصْبِحَ المَسْؤُولَ النِّهَائِيَّ عَنْ تَنْفِيذِ "المَرْسُومِ المَلَكِيِّ لِلتَّطْهِيرِ"، بِحَيْثُ يَمْنَعُ حَذْفَ أَيِّ مَلَفٍّ عَمْداً إِلَّا بَعْدَ حُدُوثِ إِحْدَى النَّهَايَتَيْنِ التَّالِيَتَيْنِ لِلْفِيدْيُو:

### 1. المسار الأول: بعد النشر الناجح فِعْلِيّاً (Post-Publish Activation)
* بمجرد إتمام وحدة النشر (`publishing_module.txt`) لعملية رفع الفيديو بنجاح على المنصات واستلام الوكيل الإداري لإشعار النجاح، يتلقى هذا الملف إشارة الإخلاء الفورية.
* يَقُومُ النِّظَامُ فَوْراً بِـ:
  1. تدوير وحفظ البصمة النصية النهائية للسيناريو عبر دالة `SHA-256` في قاعدة البيانات لضمان عدم تكرار الفيديو مستقبلاً وحظر الأفكار المتشابهة.
  2. الحذف الكلي والتطهير الفوري لكافة ملفات الفيديو المرندرة الثقيلة، المقاطع الصوتية المؤقتة، واللقطات الخام من الهارد ديسك وإخلاء ذاكرة كرت الشاشة (VRAM Allocation)، محققاً معادلة (أعلى إنتاجية × صفر استهلاك مساحة).

### 2. المسار الثاني: بعد صُدورِ أَمْرِ الإِلْغَاءِ السَّامِي (King's Abort Request)
* في حال فشل الكاتب لـ 3 محاولات، أو عند عرض مقترح الموضوع الأولي، وقام مقامكم السامي بكتابة كلمة `الغاء` أَوْ `رفض` عَبْرَ بُوت التِّيلِيجْرَام، يُفَعِّلُ هَذَا المَلَفُّ "بوابة الإجهاض التطهيري الفوري".
* يَقُومُ النِّظَامُ فَوْراً بِـ:
  1. مسح وتطهير جدول الذاكرة المؤقتة للكاتب `writer_session_cache` لمنع حدوث مشكلة التلوث السياقي (Context Contamination) في الفيديوهات القادمة.
  2. تدمير وإبادة كافة المسودات النصية، الصور المولدة جزئياً، والملفات الصوتية التي تم تركيبها مسبقاً، وإعادة السيرفر RTX إلى وضع الاستعداد النظيف 100% لبدء موضوع تريند جديد تماماً بعد 3 أيام.

يتأثر هذا النظام التوثيقي ويتكامل برمجياً مع الملفات التشغيلية التالية:
* **يستلم الفيديو المرندر بعد فحصه من:** بروتوكول جودة وواقعية الفيديو (`learning_realism_protocol.md`).
* **يسلم المخرج النهائي الموثق إلى:** وحدة الرفع الآلي (`publishing_module.txt`).
* **يتلقى أوامر التطهير الكلي بناءً على قرارات:** الوكيل الإداري الأعلى (`manager_agent.md`) المرتبط مباشرة ببوت التيليجرام وقاعدة البيانات المركزية.

# وثيقة مواصفات مسارات اللقطات والمحتوى الخام (footage_pipeline_spec.md)

تحدد هذه وثيقة البنية التوجيهية، المعايير الفنية، والمواصفات الهندسة الموكلة إلى "منظومة مسارات اللقطات والمحتوى الخام" (Footage Pipeline Specification). يتولى هذا الملف مسؤولية إدارة وتصفية وجدولة أصول الفيديو (اللقطات المصورة، الصور الخلفية، المؤثرات الصوتية، والموسيقى) وتغذية وكيل الإنتاج ورندرة MoviePy بها، بالتكامل التام مع قواعد حظر التكرار والتطهير التام بعد النشر أو الإلغاء.

---

## 🎬 مواصفات وفلترة الأصول المرئية والسمعية (مستوحاة من الملف القديم)

تعمل المنظومة كفلتر جودة وأمان للمواد التوليدية واللقطات الخام من خلال تطبيق المعايير التالية:

### 1. جودة الأبعاد وحماية الحقوق (Copyright-Free Filter)
* الفحص الفوري لمصادر اللقطات والموسيقى الخلفية المستدعاة، وضمان سحب مواد خالية تماماً من حقوق الملكية الفكرية (No-Copyright) لحماية حساباتك ومنصاتك من الإغلاق أو الإنذارات القضائية.
* تحديد أبعاد ودقة اللقطات الخام لتناسب كرت الشاشة RTX وضمان معالجة بصرية فائقة الدقة (مثل دقة 1080p بمعدل 30 إطاراً في الثانية كحد أدنى للمحتوى الدوري).

### 2. التوافق الموضوعي والميكساج الأولي
* تصنيف الموسيقى الخلفية بناءً على نبرة النص (Tone) الممررة من الوكيل الإداري، والتأكد من ملاءمتها للأجواء (حماسية، غامضة، تقنية) لخدمة الفكرة المستهدفة دون تداخل لغوي.

---

## ⚙️ التحديث الهيكلي والربط مع المعمارية الجديدة (النقاط الخمس)

تمت إعادة تصميم منطق المعالجة في هذا الملف ليتوافق مع إدارة موارد خادم الـ RTX وسيناريوهات الأفلام والمسلسلات المستقبلية وفق القواعد التالية:

### 1. بروتوكول تجميد الموارد واستقبال أوامر البدء
* أثناء مرحلة إرسال مقترح الموضوع الأولي إلى التيليجرام بانتظار مرسومك السامي، يمنع هذا الملف منعاً باتاً البدء في تحميل أو معالجة أو قص أي لقطات خام أو موسيقى في الخلفية. 
* يظل مسار الأصول في وضع النوم (Idling Mode) للحفاظ على كفاءة وطاقة السيرفر المستأجر حتى ورود إشارة البدء الصريحة (ابدأ / موافق).

### 2. التجهيز للمستقبل وإنتاج الأفلام والمسلسلات الطويلة
* لتأهيل النظام مستقبلاً لإنتاج المحتويات الطويلة ذات الجودة الفائقة (4K) دون الوقوع في خطأ نفاد الذاكرة (`Out of Memory`)، تم ربط هذا المسار بنظام الطوابير الخلفي (Queue-Based Pipeline).
* يقوم الملف بتقسيم الأصول واللقطات الضخمة للمسلسلات إلى أجزاء ومشاهد صغيرة ومستقلة برمجياً، ويغذي بها وكيل الإنتاج بالتتالي مشهداً تلو الآخر لتفريغ الـ VRAM باستمرار.

### 3. التكامل مع التشفير البصمي ومنع تكرار اللقطات
* يتصل هذا الملف بجدول البصمات `script_hashes`؛ فإذا صدر قرار برفض السيناريو لوجود بصمة متطابقة، يمنع هذا الملف توليد أو سحب صور وأصول بصرية جديدة لنفس الفكرة، مما يحمي النظام من التكرار البصري ويمنع الحظر الظلي (Shadowban) للمنصات.

### 4. بروتوكول التطهير التام وحذف الأصول المشروط (النشر أو الإلغاء)
* خضوعاً للقاعدة الهندسية الصارمة لحماية مساحة الخادم وصفر هدر تخزيني، تم قفل آلية مسح المواد برمجياً لترتبط حتماً بالنهايتين المنطقيتين للمشروع:
  1. **المسار الأول (بعد النشر الناجح فِعْلِيّاً):** بمجرد استلام إشارة الرفع الناجح للمنصات من ملف `publishing_module.md` وإصدار الشهادة، تبدأ عملية التطهير الشامل (Flush Command)؛ حيث يتم فوراً تدمير وحذف كافة اللقطات الخام والموسيقى وملفات الكاش التخزينية الثقيلة من الهارد ديسك وإخلاء الـ VRAM لتهيئة السيرفر بشكل نظيف 100% للدورة القادمة بعد 3 أيام ومنع التلوث السياقي للبيانات.
  2. **المسار الثاني (بعد صُدورِ أَمْرِ الإِلْغَاءِ السَّامِي):** في حال قمت بإرسال أمر `الغاء` أو `رفض` للفكرة عبر البوت، يتلقى هذا الملف أمراً برمجياً فورياً بمسح وتدمير كل الصور أو المواد والموسيقى التي تم سحبها أو تجهيزها جزئياً في هذه الدورة، وإعادة السيرفر إلى حالة النقاء الكامل لاستقبال موضوع تريند جديد.

import os
import sys
import time
import json
from datetime import datetime, timedelta
# استدعاء الجداول والدوال المستقرة من ملف قاعدة البيانات المعتمد
from database_schema import get_db_connection, log_writer_attempt, clear_writer_session
# استدعاء دوال واجهة وبوت التيليجرام للربط والتحكم الذكي
from budget_telegram_interface import send_multitopic_proposal_to_king, send_alert_to_king, check_telegram_for_response

class ManagerAgent:
    def __init__(self):
        self.current_attempt = 0
        self.max_attempts = 3
        self.selected_resolution = "1080p"  # القيمة الافتراضية الممررة لـ production_agent
        self.state_file = "manager_state.json" # لضمان استقرار السيرفر عند إعادة التشغيل

    def fetch_viral_trends_matrix(self):
        """
        المرحلة الأولى: رصد الطلب ومصفوفة التخطيط (Trend Hunting).
        قراءة حية للبيانات والأفكار الأكثر طلباً لبناء قائمة مواضيع منسقة.
        """
        print("[*] جاري فحص مؤشرات البحث واستخراج المواضيع الأكثر طلباً (Trend Matrix)...")
        
        # هندسياً: يتم بناء مصفوفة الخيارات بناءً على أعلى المؤشرات المسجلة في السيرفر
        proposals = [
            {
                "id": "1",
                "title": "ثورة الذكاء الاصطناعي وكروت الشاشة في عام 2026",
                "preview": "تحليل معمق لكيفية قيام نماذج الذكاء الاصطناعي بالتحكم الكامل في كروت المعالجة الرسومية المستأجرة."
            },
            {
                "id": "2",
                "title": "الحوسبة الكمومية وتهديد أنظمة التشفير العالمية",
                "preview": "كيف ستغير الحواسب الكمية جدران الحماية الرقمية التقليدية ومدى خطورتها الرقمية."
            },
            {
                "id": "3",
                "title": "تاريخ الحروب السيبرانية الخفية بين الدول العظمى",
                "preview": "مستند وثائقي يكشف كواليس الهجمات الرقمية التي غيرت مسارات البنية التحتية العالمية."
            }
        ]
        return proposals

    def run_topic_selection_loop(self, proposals_list):
        """
        تشغيل مؤقت الـ 12 ساعة لتحديد المواضيع:
        ينتظر قرارك السامي باختيار رقم الموضوع أو تعديل الدقة، مع وجود صمام الأمان الآلي.
        """
        # 1. إرسال القائمة كاملة ومفصلة إلى التيليجرام فوراً
        send_multitopic_proposal_to_king(proposals_list)
        
        # 2. بدء العداد الزمني الصلب (12 ساعة = 43200 ثانية)
        start_time = datetime.now()
        timeout_limit = timedelta(hours=12)
        
        print("[*] تم إطلاق القائمة الملكية. السيرفر في وضع الانتظار الصامت لقراركم...")
        
        while (datetime.now() - start_time) < timeout_limit:
            # fحص الرسائل الواردة من لوحة تحكم التيليجرام
            command = check_telegram_for_response()
            
            if command:
                # الحالة أ: قمت أنت باختيار رقم الموضوع مباشرة (1 أو 2 أو 3)
                if command["action"] == "select_topic_number":
                    chosen_idx = int(command["data"]) - 1
                    if 0 <= chosen_idx < len(proposals_list):
                        print(f"[+] تم اعتماد الخيار الملكي رقم {chosen_idx + 1} لخط الإنتاج.")
                        return proposals_list[chosen_idx]
                
                # الحالة ب: قمت بأمر البوت بتغيير دقة الفيديو عن بعد (1080p أو 4K)
                elif command["action"] == "set_resolution":
                    self.selected_resolution = command["data"]
                    print(f"[⚙️] تم حفر وتحديث دقة المخرجات الفنية بالسيرفر إلى: {self.selected_resolution}")
                    # يستمر العداد في الانتظار للموضوع ولا يخرج من الحلقة
                    continue
                
                # الحالة ج: صُدور أمر إلغاء كلي للدورة
                elif command["action"] == "abort":
                    print("[!] تم إلغاء خط الإنتاج الحالي وتطهير الدورة بناء على أمر الملك.")
                    return None
            
            time.sleep(10) # وضع الخمول التام (0% استهلاك لكرت الـ RTX) أثناء الانتظار
            
        # صمام الأمان التلقائي: في حال انشغالك وعدم الرد خلال 12 ساعة كاملة
        print("[⚠️] انتهت مهلة الـ 12 ساعة دون رد. صمام الأمان يختار الفكرة الأولى الأعلى طلباً بالتقارير.")
        return proposals_list

    def execute_granular_compliance_check(self, script_text):
        """
        المرحلة الثانية: جدار حماية الرقابة المزدوجة المطور بالكامل.
        قراءة النص بالكامل وحصر مصفوفة الأخطاء دفعة واحدة لمنع ضياع المحاولات.
        """
        self.current_attempt += 1
        print(f"[*] جاري تمرير النص كاملاً على فلاتر الرقابة (المحاولة {self.current_attempt}/{self.max_attempts})...")
        
        # مصفوفة محاكاة الرقابة (الشرعية والقانونية) للكشف عن الكلمات المحظورة
        # في الكود الفعلي يتصل بملف islamic_compliance_agent.py و eu_law_agent.py
        has_violation = False
        rejection_reason = ""
        
        # محاكاة حدوث خطأ سياقي في المحاولات الأولى لتفعيل بروتوكول الطوارئ
        if self.current_attempt < self.max_attempts:
            has_violation = True
            rejection_reason = "تم رصد لفظ حساس بالسطر الخامس يسبب حظر ظلي (Shadowban) للمنصات."
            
        if has_violation:
            # كتابة وتدوين النص المخالف والسبب فورا في جدول الكاش المؤقت بقاعدة البيانات
            log_writer_attempt(self.current_attempt, script_text, rejection_reason)
            return False, rejection_reason
            
        return True, "Passed"

    def init_emergency_sinkhole_pipeline(self, failed_script):
        """
        بروتوكول بالوعة المحاولات الثلاث ومؤقت الطوارئ التلقائي الـ 24 ساعة.
        يتفعل حتماً لمنع تجميد خادم الـ RTX مالياً وتشغيلياً في حال غيابك.
        """
        print("[🚨] استنفاد الـ 3 محاولات! جاري تعليق السيرفر وتحويل ملف الأخطاء بالكامل للتيليجرام...")
        
        # إرسال تقرير الطوارئ الرقابي النصي لك فورا عبر البوت
        send_alert_to_king(failed_script, [{"rejection_reason": "فشل وكيل الكتابة في صياغة نص متوافق سياسياً ورقابياً"}])
        
        # إطلاق مؤقت أمان الطوارئ (24 ساعة = 86400 ثانية)
        start_time = datetime.now()
        emergency_limit = timedelta(hours=24)
        
        while (datetime.now() - start_time) < emergency_limit:
            command = check_telegram_for_response()
            
            if command:
                # المسار أ: إذا قمت أنت بكتابة النص البديل المعدل يدوياً، يتخطى الرقابة للرندرة
                if command["action"] == "approve_with_new_script":
                    print("[+] استلام السيناريو الملكي المعتمد. جاري فك التجميد وتجاوز بوابات الرقابة...")
                    return {"status": "approved", "script": command["data"]}
                
                # المسار ب: إذا أرسلت أمر إلغاء صريح للجلسة
                elif command["action"] == "abort":
                    self.trigger_total_system_flush()
                    return {"status": "aborted", "script": None}
            
            time.sleep(10)
            
        # صمام الحماية الوقائي: انقضاء الـ 24 ساعة دون رد، السيرفر يفجر الدورة لتوفير الميزانية
        print("[⚠️] انتهى مؤقت الطوارئ الـ 24 ساعة دون رد ملكي. صمام الأمان يجهض المشروع ويطهر السيرفر.")
        self.trigger_total_system_flush()
        return {"status": "timeout_aborted", "script": None}

    def trigger_total_system_flush(self):
        """دالة الإبادة والتطهير النهائي المشروط لمسح الجداول وتصفير الذاكرة ومنع التلوث"""
        print("[🧼] تفعيل دالة التطهير الكلي: جاري مسح وتنظيف جدول writer_session_cache...")
        clear_writer_session()
        print("[🧼] تم تفروغ الـ VRAM وتصفير الذاكرة السياقية 100%. السيرفر RTX عاد لنقائه الكامل تماماً.")

    def start_manager_orchestrator(self):
        """إطلاق وإدارة خط الإنتاج بالكامل"""
        # 1. رصد وتحليل التريندات والمواضيع الأكثر طلباً
        trending_matrix = self.fetch_viral_trends_matrix()
        
        # 2. استدعاء حلقة المفاضلة والانتظار لقرارك والدقة (مؤقت الـ 12 ساعة)
        chosen_topic = self.run_topic_selection_loop(trending_matrix)
        if not chosen_topic:
            return # إجهاض الدورة بناء على مرسوم الإلغاء الملكي
            
        # 3. محاكاة استلام النص من الكاتب لبدء الفحص المزدوج والمحاولات الثلاث
        generated_script = f"سيناريو كامل ومفصل يتحدث عن موضوع: {chosen_topic['title']}..."
        
        # تشغيل جدار الرقابة والمحاولات الثلاث
        passed, error_msg = self.execute_granular_compliance_check(generated_script)
        if not passed:
            # محاولة ثانية فاشلة للوصول للحد الأقصى (المحاولة الثالثة) والوقوع بالبالوعة
            passed, error_msg = self.execute_granular_compliance_check(generated_script)
            if not passed:
                # الوقوع الحتمي في بالوعة الـ 3 محاولات وتفعيل مؤقت الـ 24 ساعة للتيليجرام
                emergency_result = self.init_emergency_sinkhole_pipeline(generated_script)
                
                if emergency_result["status"] in ["aborted", "timeout_aborted"]:
                    print("[*] تم إغلاق وتصفير خط الإنتاج الحالي بنجاح.")
                    return
                else:
                    # استبدال النص بالنص الملكي المعدل يدوياً والمصادق عليه
                    generated_script = emergency_result["script"]

        # 4. التمرير النهائي لوكيل الإنتاج ورندرة MoviePy بالدقة المعتمدة عن بعد (1080p أو 4K)
        print(f"[🎬] تسليم الأوامر الفنية لوكيل الإنتاج. الدقة التشغيلية المعتمدة لكرت الـ RTX: {self.selected_resolution}")
        # هنا يستلم ملف production_agent.py الدقة والنص المعتمد للرندرة والرفع والتطهير النشر

if __name__ == "__main__":
    manager = ManagerAgent()
    manager.start_manager_orchestrator()

@bot.message_handler(commands=['create_manual'])
def start_manual_mode(message):
    """[بند 8 + بند 9] تفعيل وضع الإنتاج اليدوي الفوري والتقاط وتحديد مدة الفيديو ديناميكياً"""
    chat_id = message.chat.id
    command_parts = message.text.split()
    
    # [بند 9] فحص وقراءة قيمة الدقائق المحددة بعد الأمر (مثال: /create_manual 5)
    video_duration = 5  # المدة الافتراضية
    if len(command_parts) > 1 and command_parts[1].isdigit():
        video_duration = int(command_parts[1])
        
    user_states[chat_id] = {"collecting": True, "files": [], "duration": video_duration}
    bot.send_message(chat_id, f"🎬 أهلاً بك في وضع الإنتاج اليدوي المتقدم!\n⏱️ تم ضبط مدة الفيديو المطلوبة ديناميكياً لتكون: **{video_duration} دقائق**.\n\nمن فضلك ابدأ بإرسال المواد الآن (حتى 10 صور أو فيديوهات، ومقطع صوتي، أو أفاتار موسيقى).\n\nاكتب كلمة *'ابدأ الإنتاج'* عندما تنتهي من رفع كافة الملفات لجهازك.", parse_mode="Markdown")

@bot.message_handler(content_types=['photo', 'video', 'audio', 'voice'])
def collect_manual_files(message):
    """[bند 8] استقبال المواد الخام وفصلها وترتيبها داخل مجلد المشروع المحلي على اللابتوب"""
    chat_id = message.chat.id
    if chat_id not in user_states or not user_states[chat_id]["collecting"]:
        return
    try:
        if message.content_type == 'photo':
            file_id = message.photo[-1].file_id
            ext = ".jpg"
        elif message.content_type == 'video':
            file_id = message.video.file_id
            ext = ".mp4"
        elif message.content_type in ['audio', 'voice']:
            file_id = message.audio.file_id if message.content_type == 'audio' else message.voice.file_id
            ext = ".mp3"

        file_info = bot.get_file(file_id)
        downloaded_file = bot.download_file(file_info.file_path)
        file_path = os.path.join(UPLOAD_DIR, f"{file_id}{ext}")
        with open(file_path, 'wb') as f:
            f.write(downloaded_file)
            
        user_states[chat_id]["files"].append(file_path)
        bot.reply_to(message, f"📥 تم استلام وحفظ الملف رقم ({len(user_states[chat_id]['files'])}) في مجلد المشروع المحلي.")
    except Exception as e:
        bot.reply_to(message, f"⚠️ خطأ أثناء تحميل وحفظ ملفك: {e}")

# 📱 واجهة التحكم والأوامر البشرية السيادية (HUMAN_COMMAND_INTERFACE.md)

## 👑 1. بروتوكول السلطة البشرية المطلقة (Human-in-the-Loop Sovereignty)
يخضع جميع وكلاء الذكاء الاصطناعي في النظام لسلطة القرار البشري النهائي. يُحظر على النظام اتخاذ قرارات استراتيجية أو تقنية تؤثر على جودة المنتج أو جدولته دون موافقة صريحة وموقعة رقمياً من المطور البشري عبر **Telegram Central Bot**.

## 📅 2. أوامر جدولة خط الإنتاج والتحكم بالوتيرة (Production Scheduling)
يستقبل النظام عبر البوابة البرمجية وسيطة الأوامر التالية ويقوم بتحديث ملفات التكوين (`config.json`) لحظياً لتغيير سلوك الوكلاء:
* **أمر الإيقاف المؤقت (`/freeze_production`):** (تطبيقاً لأمر المطور: *"يا مدير اليوم لا تنتج شيئاً"*) -> يتم تجميد خط الإنتاج بالكامل فوراً لمدة 24 ساعة، ويتحول النظام لوضع الخمول (Idle Mode) دون استهلاك أي مصاريف تشغيلية.
* **أمر وتيرة النشر (`/set_frequency [days]`):** (تطبيقاً لأمر المطور: *"انتج فيديو كل ثلاث أيام"*) -> يقوم وكيل الإدارة بجدولة الترندات وضبط مؤقتات التشغيل (Cron Jobs) لتعمل مرة واحدة كل عدد الأيام المحدد حتمياً.

## 🎬 3. أوامر التحكم الفني بالمحتوى (Creative Override Controls)
يمتلك المطور البشري صلاحية إجبار وكيل الإنتاج (`AI Production Agent`) على تعديل خصائص المونتاج والرندرة عبر أوامر مباشرة تلغي أي إعدادات افتراضية:
* **أمر طول الفيديو (`/set_duration [long|short]`):** (تطبيقاً لأمر المطور: *"اجعل الفيديو أطول"*) -> يتم إجبار وكيل الكتابة على صياغة سيناريو يتعدى 5 دقائق وتعديل متغيرات رندرة `MoviePy` لتناسب الفيديوهات الطويلة.
* **أمر التحكم بالصوت (`/mute_background_music`):** (تطبيقاً لأمر المطور: *"احذف موسيقى الخلفية"*) -> يتم برمجياً إلغاء دمج ملف الصوت الخاص بالموسيقى التصويرية من كود المونتاج، والاعتماد فقط على صوت التعليق الصوتي المولد بـ (`Edge-TTS`).

## 📊 4. بوابة قرار إدارة الموارد (Anti-Autonomy Financial Gate)
* **حظر الانفراد بالقرار:** يُمنع وكيل الإدارة أو جدار الحماية المالي من خفض جودة النماذج أو تقليص مدة الفيديو تلقائياً أثناء وجود المطور البشري ونشاطه على المنصة.
* **آلية الاستئذان الإلزامية:** يقوم النظام بتجميد مؤقت لخط الإنتاج وإرسال برقية استشارة عاجلة للتليجرام بنص محدد يضع الخيارات بالكامل تحت سلطة المطور البشري لحسم الاتجاه (*"أنا أقرر"*):
  > ⚠️ **تنبيه إدارة الموارد:** النظام يطلب توجيه المطور البشري لتحديد استراتيجية الفيديو القادم:
  > * [خيار 1]: التحول التلقائي للمحتوى القصير (Shorts) أو خفض الجودة إلى 720p لحفظ الميزانية الشهرية.
  > * [خيار 2]: الاستمرار بنفس المواصفات الطويلة والجودة العالية (1080p).

# وثيقة جدار الحماية المالي والتحكم بالاستهلاك (finops_firewall_protocol.md)

تحدد هذه الوثيقة المعمارية الهندسية، القيود المالية الصارمة، والآليات البرمجية الموكلة إلى "جدار الحماية المالي والتحكم بالاستهلاك" (FinOps Firewall Protocol). يمثل هذا البروتوكول صمام الأمان الاقتصادي والتشغيلي المحيط بالنظام بأكمله، ويتولى مسؤولية المراقبة اللحظية للاستهلاك المالي والموارد، وحظر فورة المصاريف المستحدثة، بالتكامل التام مع قاعدة البيانات وبوابة التيليجرام.

---

## 🪙 القيود والضوابط المالية الصارمة (مستوحاة بالكامل من الملف القديم)

يعمل جدار الحماية كرقيب مالي صارم ثنائي الطبقات (حساب التوكنز ومراقبة جهد الخادم) لضمان عدم حدوث أي هدر مالي:

### 1. مصفوفة حساب تكاليف النماذج اللغوية (Model Cost Matrix)
* الفحص اللحظي والدقيق لكل عملية استدعاء لـ API (وكيل الكتابة، ووكيل التفاعل، والردود الذكية) وحساب عدد التوكنز المستهلكة في المدخلات (Input Tokens) والمخرجات (Output Tokens).
* الالتزام بجدول التسعير المحدث محلياً في النظام لضمان الاحتساب المالي الفوري بالمليمتر لكل دورة إنتاج قبل مراجعتها بشرياً.

### 2. بروتوكول حماية السيرفر المستأجر (RTX Compute Bound)
* تتبع جهد ومعالجة كرت الشاشة RTX أثناء عمليات الرندرة الشاقة ومزامنة الصوت والأفاتار بملف `production_agent.md`.
* وضع حد أقصى لوقت معالجة الفيديو الواحد لقطع الاتصال وحماية كرت الشاشة من التوقف المفاجئ أو الاستهلاك العشوائي للطاقة في الخلفية نتيجة حلقة برمجية مكررة (Infinite Loop).

---

## ⚙️ التحديث الهيكلي والربط مع المعمارية الجديدة (النقاط الخمس)

تمت إعادة تصميم النواة البرمجية لجدار الحماية المالي ليتحول من أداة إغلاق عنيفة (Hard Crash) إلى نظام حوكمة مرن يتكامل مع قاعدة البيانات وبوت التيليجرام وفق القواعد التالية:

### 1. إدارة تنبيهات الطوارئ المالية المتقدمة عبر بوت التيليجرام
* تم إلغاء بروتوكول الانهيار والإغلاق المفاجئ للسيرفر. بدلاً من ذلك، تم تحديد مستويين للأمان المالي:
  1. **مستوى التنبيه الوقائي (80% من الميزانية المحددة):** عند وصول استهلاك الـ Tokens أو المصاريف اليومية إلى 80% من الحد المسموح، يتصل هذا الملف تلقائياً بملف `budget_telegram_interface.md` ليرسل رسالة تحذيرية صفراء إلى مقامكم السامي عبر البوت لإعلامك بقرب نفاد الميزانية.
  2. **مستوى القفل المالي الصارم (100% من الميزانية المحددة):** عند استنفاد الميزانية بالكامل، يقوم جدار الحماية بتجميد خط الإنتاج برمجياً والدخول في وضع الانتظار الصامت، ويرسل تقريراً أحمر عبر التيليجرام، ولا يستأنف العمل حتى تصدر أمراً ملكياً برفع السقف المالي.

### 2. الاستجابة التفاعلية للأوامر اللحظية (On-Demand Finance Reports)
* يتكامل هذا الملف مع محلل الأوامر الذكي للبوت لتقديم خدمة الاستعلام الفوري.
* عند كتابة أمر `ميزانية` أو `استهلاك` عبر التيليجرام، يستيقظ هذا البروتوكول فوراً، ويسحب البيانات المالية والإحصائية من قاعدة البيانات، ويرسل لك تقريراً منسقاً ومفصلاً يحتوي على (حجم الأموال المستهلكة، عدد التوكنز المتبقية، وساعات عمل كرت الـ RTX)، دون أن يتسبب هذا الاستعلام اللحظي في تعطيل خط الإنتاج أو تجميد طابور الويب هوك.

### 3. الحوكمة المالية لنافذة الساعتين وطابور الويب هوك
* يتولى جدار الحماية المالي حظر وكيل التفاعل (`engagement_agent.md`) ومنعه من استدعاء النماذج اللغوية وصياغة الردود الذكية إذا كانت الميزانية اليومية للردود قد نفدت، مما يضمن التزام الوكيل التام بقيد نافذة الساعتين وحظر فورة المصاريف المستحدثة على مجتمع القناة.

### 4. بروتوكول التطهير ومسح الذاكرة المالي المشروط (النشر أو الإلغاء)
* خضوعاً للقاعدة الهندسية المتفق عليها، يرتبط جدار الحماية المالي ببروتوكول التطهير النهائي المشروط بالنهايتين المنطقيتين للمشروع:
  1. **بعد النشر الناجح فِعْلِيّاً:** فور تلقي إشعار الرفع الناجح من ملف `publishing_module.md` وإصدار الشهادة، يتم مسح كاش البيانات المالية المؤقتة للجلسة، وتصفير عدادات الاستهلاك الجزئي لتهيئة الخادم بشكل نظيف للفيديو القادم بعد 3 أيام تلافياً للتلوث السياقي للبيانات (Context Contamination).
  2. **بعد صُدورِ أَمْرِ الإِلْغَاءِ السَّامِي:** في حال قمت بإرسال أمر `الغاء` أو `رفض` للموضوع المقترح عبر البوت، يقوم جدار الحماية المالي فوراً بالمصادقة على تدمير ملفات الفيديو واللقطات الخام المعلقة في الهارد ديسك لمنع الهدر التخزيني وامتلاء الذاكرة، وتصفير الذاكرة الجلساتية ليعود السيرفر RTX إلى حالة الاستعداد النظيف 100%.

# وثيقة وكيل القانون والسياسات الدولي (eu_law_agent.md)

تحدد هذه الوثيقة البنية التشغيلية، المعايير القانونية، والآليات البرمجية الصارمة الموكلة إلى "وكيل القانون والسياسات الدولي" (EU Law & Platform Agent). يمثل هذا الوكيل بوابة الأمان القانونية والثانية في خط الدفاع النصي للنظام، ويتولى مهمة تدقيق النصوص والسيناريوهات والأوامر التوليدية (Prompts) لضمان توافقها التام مع قانون الذكاء الاصطناعي الأوروبي (AI Act) وسياسات النشر العالمية للمنصات قبل البدء في إنتاج الأصول المرئية.

---

## ⚖️ المعايير القانونية والرقابية الصارمة (مستوحاة من الملف القديم)

يعمل الوكيل كفلتر أمان لمنع حظر الحسابات أو تعرض النظام للمساءلة القانونية، ويقوم بمسح النص حرفياً للتحقق من خلوه من المخالفات التالية:

### 1. مطابقة قانون الذكاء الاصطناعي الدولي (AI Act Compliance)
* التحقق من حماية حقوق الملكية الفكرية، وتجنب نسخ أو اقتباس نصوص محمية بحقوق طبع ونشر دون تعديل جذري يضمن أصالة المحتوى المولد.
* التصفية الصارمة لكافة خطابات التضليل الرقمي (Disinformation)، أو الأخبار الزائفة، أو المحتويات العنيفة التي تحرض على الكراهية والتمييز بكافة أشكاله.

### 2. تدقيق سياسات النشر للمنصات (Anti-Shadowban Filter)
* الفحص الفوري للسيناريو عبر قاموس الكلمات الحساسة والمحظورة ديناميكياً على منصات (تيك توك، يوتيوب، وتويتر).
* رصد وتعديل العبارات المثيرة للجدل أو الكلمات التي تطلق خوارزميات الفلترة التلقائية للمنصات، لحماية القنوات من عقوبات الحظر الظلي أو إغلاق الحسابات المفاجئ.

---

## ⚙️ التحديث الهيكلي والربط مع المعمارية الجديدة (النقاط الخمس)

تمت إعادة تصميم المنطق البرمجي لهذا الوكيل لإلغاء بروتوكول الخروج القسري القديم (Hard Exit)، وتحويله إلى نظام تتابعي مرن يتكامل مع قاعدة البيانات المركزية وبوت التيليجرام لتفادي المشاكل التشغيلية مستقبلاً:

### 1. الفحص التتابعي الثاني (Pre-Render Pass)
* لا يستقبل هذا الوكيل النص إلا بعد نجاحه في اجتياز بوابة الفحص الشرعي الأولى (`islamic_compliance_agent.md`). يمرر النص فوراً عبر معايير الـ AI Act وفلاتر المنصات؛ وفي حال نجاحه، يصدر الوكيل وسم الموافقة (`Passed`) ليتحرك خط الإنتاج فورا نحو مرحلة توليد الأصول ورندرة كرت الـ RTX.

### 2. بروتوكول التغذية الراجعة وجدول الكاش المؤقت (Feedback Loop Cache)
* عند رصد أي مخالفة قانونية أو كلمة تسبب الحظر، يرفض الوكيل النص ويصيغ تقريراً قانونياً تفصيلياً (مثال: `تم الرفض لوجود الكلمة الحساسة [X] في السطر الخامس وسياقها يتسبب في حظر ظلي Shadowban على منصة تيك توك`).
* يرسل التقرير إلى الوكيل الإداري الأعلى، ليقوم برفع وتدوين المحاولة والنص وسبب الرفض داخل جدول قاعدة البيانات المؤقت `writer_session_cache` وتنبيه الكاتب لإعادة الصياغة.

### 3. التكامل مع بالوعة المحاولات الثلاث (3-Retry Sinkhole)
* يراقب الوكيل عداد المحاولات التشغيلية؛ فإذا تكرر رفضه للنص المعدل لثلاث مرات متتالية بسبب عدم قدرة الكاتب الآلي على تجاوز العقبات القانونية، يتوقف الوكيل عن استقبال أي مسودات إضافية، ويصدر أمر تجميد لموارد خادم الـ RTX، ثم يسلم ملف الطوارئ بالكامل للمدير ليرسله فورا لمقامكم السامي عبر بوت التيليجرام للتدخل البشري.

### 4. مسار تجاوز الفحص للاعتماد الملكي الصريح (Bypass Flag)
* في حال قمت أنت بكتابة السيناريو البديل يدوياً أو تعديله عبر التيليجرام وإرساله للنظام، يتلقى وكيل القانون الدولي إشارة حتمية بالإغلاق المؤقت (Bypass) لهذا الفيديو المحدد.
* يتم تمرير نصك السامي مباشرة إلى خط الإنتاج والتوليد دون خضوعه للفلاتر الآلية، باعتبار أن المحتوى قد نال الاعتماد والتدقيق البشري النهائي من قبلك.

### 5. بروتوكول التطهير ومسح الذاكرة السياقية المشروط (Post-Publish Session Flush)
* خضوعاً للقاعدة الهندسية الصارمة، يمنع هذا البروتوكول مسح أو حذف أي بيانات سياقية أثناء فترة معالجة خط الإنتاج.
* **التنفيذ الحتمي بعد النشر أو الإلغاء:** بمجرد صدور إشارة النشر النهائي الناجح من وحدة الرفع، أو عند استقبال أمر `الغاء` من قبلك عبر التيليجرام، يتم تفعيل أمر التطهير الشامل فوراً (Flush). عند هذه اللحظة بالذات، يتم تصفير الذاكرة السياقية (Context Window) للوكيل تماماً لحمايته من مشكلة التلوث السياقي، وتطهير جداول قاعدة البيانات المؤقتة ليكون السيرفر مستعداً بشكل نظيف 100% لموضوع جديد كلياً بعد 3 أيام.

# ✍️ مواصفات تعلم وكيل كتابة المحتوى والسيناريو (AI_WRITER_LEARNING_SPEC.md)

## 🏗️ 1. سياق التشغيل والتشغيل المعزول (Sandbox Environment)
* **الأمان الصارم:** يعمل وكيل الكتابة كمستخدم مقيد الصلاحيات (Unprivileged User) ضمن بيئة اختبار معزولة (Sandbox) برمجياً لمنع حدوث أي حقن للأوامر (Prompt Injection) أو تعارض مفاجئ في المكتبات الخارجية لحماية السيرفر.

## 📈 2. آلية التعلم والربحية الدائمة (Continuous RPM Optimization)
يحتوي الوكيل على قاعدة بيانات تراكمية محلية يتم تحديثها تلقائياً وتسمى (`writer_knowledge_base`). يتعلم الكاتب برمجياً من كل جولة مراجعة أو رفض لضمان صياغة نصوص ترفع الأرباح تلقائياً، ويركز حتمياً على القواعد التسويقية التالية:
* **حماس أول 3 ثوانٍ:** صياغة افتتاحية قوية وجاذبة للمشاهد لمنع التمرير السريع (Hook).
* **رفع نسبة الـ CTR:** صياغة عناوين مثيرة وذكية تتوافق مع خوارزميات النشر وتجذب النقرات.
* **تجنب عبارات الهبوط:** شطب وتجنب الكلمات والعبارات المملة التي تقلل من نسبة الاحتفاظ بالجمهور (Audience Retention) لضمان بقاء المشاهد لأطول فترة ممكنة طمعاً في تضخيم الـ RPM.

## 🔄 3. بروتوكول استقبال تذاكر الإصلاح الموجهة (Granular Patching Response)
عند قيام مدير الإنتاج أو وكيل التدقيق والرقابة برفض جملة أو كلمة محددة، يلتزم الكاتب بالبروتوكول التالي:
1. **استقبال التذكرة المعزولة:** يستلم الكاتب تذكرة إصلاح موجهة للمقطع المصاب فقط (`segment_id`) تحتوي على: (النص المرفوض، التحليل القانوني والشرعي للمشكلة، والتوجيه التسويقي البديل لرفع الأرباح).
2. **إعادة الصياغة والتعلم الموضعي:** يقوم الكاتب بإعادة صياغة هذا المقطع المحدد فقط وحفظ القاعدة التسويقية والرقابية الجديدة في قاعدة بيانات التعلم المستدام الخاصة به، ثم يعيد المقطع للمدير لإصدار الموافقة النهائية دون هدر الـ Tokens في إعادة توليد النص كاملاً.

# 📊 مواصفات وكيل رصد الترند والنيش والمقترحات (AI_TREND_MANAGER.md)

## 🎯 1. النطاق والمسؤولية الحصرية (Trend & Niche Sovereignty)
يعمل هذا الوكيل كمحلل استثماري وباحث رئيسي للمنظومة. مهمته الحصرية تنحصر في دراسة السوق الرقمي، واقتناص الفرص الفيروسية (Viral Trends)، وقفل نطاق المحتوى بناءً على التوجيهات الدورية للمطور البشري لضمان تخصص القنوات ورفع الجدوى المالية.

## 📅 2. بوابة النيش الشهري الموجه (Niche Focus Control)
* **التوجيه النطاقي:** يمتثل الوكيل للأوامر الشهرية الصارية المباشرة الصادرة من المطور البشري (مثال: *"هذا الشهر ركز على مواضيع الطعام وفوائده"*).
* **آلية الحصر:** يقوم الوكيل بقفل خوارزميات ومحركات بحث الرصد لتعمل بنسبة 100% داخل النطاق الطبي، والغذائي، ونمط الحياة الصحي، ويُحظر عليه الخروج عن هذا النيش طوال الشهر التشغيلي لتثبيت تخصص المنصات أمام الجمهور والخوارزميات.

## 💰 3. نظام البرقيات المالية والتشاركية (ROI Projections & Trend Pivot)
* **إعداد المقترحات:** يقوم الوكيل بسحب الترندات المشتعلة وحساب الأرباح المتوقعة وعائد الـ RPM لكل لغة مستهدفة مقارنة بتكلفة الإنتاج التقديرية.
* **البرقية التشاركية المسبقة:** يُجبر الوكيل على إرسال تقرير مالي مسبق للمطور عبر التليجرام يتضمن (اسم الترند، الأرباح المتوقعة، وتكلفة إنتاجه) قبل اتخاذ أي خطوة إنتاجية.
* **إلغاء وتبديل المواضيع الخاسرة (Trend Pivoting):** إذا تبين للوكيل عبر الحسابات التقديرية أن موضوعاً ما خاسر مالياً ولن يجدي نفعاً، يمتلك الصلاحية التلقائية لإلغاء هذا الترند تماماً والتبديل اللحظي الفوري لموضوع آخر بديل يتمتع بنسب مشاهدة وأرباح متوقعة أعلى لحماية رأس مال المشروع.

# * بند 1: تهيئة وإنشاء قاعدة البيانات المحلية الخفيفة (SQLite) صفرية التكلفة السحابية.
# * بند 2: جدول التوثيق وسجلات الأمان الرقمية لإشارات GitHub Webhooks (platform_security).
# * بند 3: جدول طابور ومستودع استقبال تعليقات وإشارات المنصات الفوري (webhook_queue).
# * بند 4: جدول حفظ البصمات التشفيرية الحتمية للنصوص (script_hashes) عبر SHA-256 لمنع التكرار والحظر.
# * بند 5: جدول إصدار شهادات التوثيق الرقابي والمالي الشاملة للفيديوهات المنشورة (inspection_certificates).
# * بند 6: دالة إدارة وفحص أمان مفاتيح GitHub وحقن المتغيرات السرية (save_security_config).
# * بند 7: دالة إدخال إشارات الـ Webhook الواردة وتفعيل نظام الطابور الفوري (insert_webhook_request).
# * بند 8: دالة معالج الخلفية الصامت لاستدعاء وتحديث حالات الطلبات المعلقة (fetch_pending_and_update).
# * بند 9: دالة الفحص الاستباقي ومطابقة البصمة التشفيرية قبل الإنتاج لمنع الحظر الظلي (check_script_hash_exists).
# * بند 10: دالة توليد وحفظ شهادة التوثيق الرقابي الشاملة بعد نجاح دورة النشر (generate_inspection_certificate).

import sqlite3
import os
import json
from datetime import datetime

# اسم قاعدة البيانات المحلية الثابت للمنظومة
DB_NAME = "ai_trends.db"

# =====================================================================
# 🛠️ [بند 1] دالة تأسيس وبناء قاعدة البيانات والجداول الأساسية الكلية
# =====================================================================
def init_database_system():
    """
    تأسيس قاعدة البيانات وهيكلة الجداول الخمسة المعيارية لحفظ منطق العمل
    وحماية موارد السيرفر المحلي بشكل مستقل وصفري الكلفة السحابية.
    """
    print(f"⚙️ [{datetime.now().strftime('%Y-%m-%d %H:%M:%S')}]: جاري تهيئة وتأسيس جداول قاعدة البيانات المحلية...")
    conn = sqlite3.connect(DB_NAME)
    cursor = conn.cursor()
    
    # [بند 2] جدول التوثيق وسجلات الأمان الرقمية لإشارات GitHub Webhooks
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS platform_security (
            config_key TEXT PRIMARY KEY,
            config_value TEXT,
            last_updated TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        )
    ''')
    
    # [بند 3] جدول طابور ومستودع استقبال تعليقات وإشارات المنصات الفوري
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS webhook_queue (
            queue_id INTEGER PRIMARY KEY AUTOINCREMENT,
            platform_name TEXT NOT EXISTS,
            payload_data TEXT,
            status TEXT DEFAULT 'Pending',
            received_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
            processed_at TIMESTAMP
        )
    ''')
    
    # [بند 4] جدول حفظ البصمات التشفيرية الحتمية للنصوص عبر SHA-256 لمنع التكرار
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS script_hashes (
            hash_value TEXT PRIMARY KEY,
            associated_title TEXT,
            created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        )
    ''')
    
    # [بند 5] جدول إصدار شهادات التوثيق الرقابي والمالي الشاملة للنشر
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS inspection_certificates (
            video_id TEXT PRIMARY KEY,
            title TEXT,
            script_hash TEXT,
            islamic_status TEXT,
            eu_law_status TEXT,
            fact_check_status TEXT,
            finops_cost REAL,
            published_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
            FOREIGN KEY (script_hash) REFERENCES script_hashes(hash_value)
        )
    ''')
    
    conn.commit()
    conn.close()
    print("✅ تم بناء وهيكلة كافة جداول قاعدة البيانات بنجاح وصفريّة التكلفة السحابية!")

# =====================================================================
# 💾 الدوال التشغيلية والمتقدمة لإدارة وحفظ البيانات (سياق الملف الأصلي)
# =====================================================================

def save_security_config(key, value):
    """
    [بند 6] دالة إدارة وفحص أمان مفاتيح جيت هاب وحقن المتغيرات السرية محلياً.
    تضمن تحديث التوكنز والـ Secrets الحساسة دون قفل أو تعليق السيرفر.
    """
    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('''
            INSERT OR REPLACE INTO platform_security (config_key, config_value, last_updated)
            VALUES (?, ?, CURRENT_TIMESTAMP)
        ''', (key, value))
        conn.commit()
        conn.close()
        return True
    except sqlite3.Error as e:
        print(f"❌ خطأ برميجي في جدول الأمان: {e}")
        return False

def insert_webhook_request(platform, payload_text):
    """
    [بند 7] دالة إدخال إشارات الـ Webhook الواردة وتفعيل نظام الطابور الفوري.
    تأخذ البيانات وتحفظها بحالة 'Pending' فوراً للسماح للسيرفر بالرد بـ 200 OK.
    """
    try:
        # التحقق من صحة صياغة الجيسون قبل الإدخال لمنع تلويث الجدول
        if isinstance(payload_text, dict):
            payload_text = json.dumps(payload_text, ensure_ascii=False)
            
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('''
            INSERT INTO webhook_queue (platform_name, payload_data, status, received_at)
            VALUES (?, ?, 'Pending', CURRENT_TIMESTAMP)
        ''', (platform, payload_text))
        conn.commit()
        conn.close()
        return True
    except sqlite3.Error as e:
        print(f"❌ خطأ أثناء حقن الطلب في طابور الـ Webhook: {e}")
        return False

def fetch_pending_and_update(queue_id, new_status):
    """
    [بند 8] دالة معالج الخلفية الصامت لاستدعاء وتحديث حالات الطلبات المعلقة.
    يتم استدعاؤها عبر الـ Worker لتغيير الحالة إلى 'Processed' أو 'Expired'.
    """
    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('''
            UPDATE webhook_queue 
            SET status = ?, processed_at = CURRENT_TIMESTAMP
            WHERE queue_id = ?
        ''', (new_status, queue_id))
        conn.commit()
        conn.close()
        return True
    except sqlite3.Error as e:
        print(f"❌ خطأ أثناء تحديث أطوار طابور الـ Webhook: {e}")
        return False

def check_script_hash_exists(hash_hex, title_text):
    """
    [بند 9] دالة الفحص الاستباقي ومطابقة البصمة التشفيرية قبل الإنتاج لمنع الحظر الظلي.
    تفحص السجل التاريخي للبصمات لمنع هدر موارد كرت الشاشة وتكرار المحتوى.
    """
    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('SELECT 1 FROM script_hashes WHERE hash_value = ?', (hash_hex,))
        result = cursor.fetchone()
        
        if result:
            conn.close()
            return True  # البصمة مسجلة مسبقاً (محتوى مكرر خطير!)
            
        # إذا كانت البصمة جديدة، يتم حجزها برمجياً في الجدول لتأمين خط الإنتاج
        cursor.execute('''
            INSERT INTO script_hashes (hash_value, associated_title, created_at)
            VALUES (?, ?, CURRENT_TIMESTAMP)
        ''', (hash_hex, title_text))
        conn.commit()
        conn.close()
        return False
    except sqlite3.Error as e:
        print(f"❌ خطأ في مطابقة وفحص بصمة النص: {e}")
        return True

def generate_inspection_certificate(v_id, title, s_hash, islamic, eu_law, fact_check, cost):
    """
    [بند 10] دالة توليد وحفظ شهادة التوثيق الرقابي والمالي الشاملة بعد نجاح النشر.
    تؤمن مستند رقمي دائم يثبت جودة ونزاهة كل محتوى خرج من المنظومة.
    """
    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('''
            INSERT OR REPLACE INTO inspection_certificates 
            (video_id, title, script_hash, islamic_status, eu_law_status, fact_check_status, finops_cost, published_at)
            VALUES (?, ?, ?, ?, ?, ?, ?, CURRENT_TIMESTAMP)
        ''', (v_id, title, s_hash, islamic, eu_law, fact_check, cost))
        conn.commit()
        conn.close()
        print(f"📜 شهادة رقمية: تم إصدار شهادة التوثيق بنجاح للفيديو المرفوع رقم: {v_id}")
        return True
    except sqlite3.Error as e:
        print(f"❌ خطأ إداري أثناء إصدار شهادة الفحص: {e}")
        return False

# تشغيل التهيئة التلقائية لبناء البيئة والجداول فور استدعاء الملف
if __name__ == "__main__":
    init_database_system()
