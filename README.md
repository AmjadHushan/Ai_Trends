# وثيقة جدار الحماية المالي والتحكم بالاستهلاك (finops_firewall_protocol.md)

تحدد هذه الوثيقة المعمارية الهندسية، القيود المالية الصارمة، والآليات البرمجية الموكلة إلى "جدار الحماية المالي والتحكم بالاستهلاك" (FinOps Firewall Protocol). يمثل هذا البروتوكول صمام الأمان الاقتصادي والتشغيلي المحيط بالنظام بأكمله، ويتولى مسؤولية المراقبة اللحظية للاستهلاك المالي والموارد، وحظر فورة المصاريف المستحدثة، بالتكامل التام مع قاعدة البيانات وبوابة التيليجرام.

---

## 🪙 القيود والضوابط المالية الصارمة (مستوحاة بالكامل من الملف القديم)

يعمل جدار الحماية كرقيب مالي صارم ثنائي الطبقات (حساب التوكنز ومراقبة جهد الخادم) لضمان عدم حدوث أي هدر مالي:

### 1. مصفوفة حساب تكاليف النماذج اللغوية (Model Cost Matrix)
* الفحص اللحظي والدقيق لكل عملية استدعاء لـ API (وكيل الكتابة، ووكيل التفاعل، والردود الذكية) وحساب عدد التوكنز المستهلكة في المدخلات (Input Tokens) والمخرجات (Output Tokens).
* الالتزام بجدول التسعير المحدث محلياً في النظام لضمان الاحتساب المالي الفوري بالمليمتر لكل دورة إنتاج قبل مراجعتها بشرياً.

### 2. بروتوكول حماية السيرفر المستأجر (RTX Compute Bound)
* تتبع جهد ومعالجة كرت الشاشة RTX أثناء عمليات الرندرة الشاقة ومزامنة الصوت والأفاتار بملف `production_agent.md`.
* وضع حد أقصى لوقت معالجة الفيديو الواحد لقطع الاتصال وحماية كرت الشاشة من التوقف المفاجئ أو الاستهلاك العشوائي للطاقة في الخلفية نتيجة حلقة برمجية مكررة (Infinite Loop).

---

## ⚙️ التحديث الهيكلي والربط مع المعمارية الجديدة (النقاط الخمس)

تمت إعادة تصميم النواة البرمجية لجدار الحماية المالي ليتحول من أداة إغلاق عنيفة (Hard Crash) إلى نظام حوكمة مرن يتكامل مع قاعدة البيانات وبوت التيليجرام وفق القواعد التالية:

### 1. إدارة تنبيهات الطوارئ المالية المتقدمة عبر بوت التيليجرام
* تم إلغاء بروتوكول الانهيار والإغلاق المفاجئ للسيرفر. بدلاً من ذلك، تم تحديد مستويين للأمان المالي:
  1. **مستوى التنبيه الوقائي (80% من الميزانية المحددة):** عند وصول استهلاك الـ Tokens أو المصاريف اليومية إلى 80% من الحد المسموح، يتصل هذا الملف تلقائياً بملف `budget_telegram_interface.md` ليرسل رسالة تحذيرية صفراء إلى مقامكم السامي عبر البوت لإعلامك بقرب نفاد الميزانية.
  2. **مستوى القفل المالي الصارم (100% من الميزانية المحددة):** عند استنفاد الميزانية بالكامل، يقوم جدار الحماية بتجميد خط الإنتاج برمجياً والدخول في وضع الانتظار الصامت، ويرسل تقريراً أحمر عبر التيليجرام، ولا يستأنف العمل حتى تصدر أمراً ملكياً برفع السقف المالي.

### 2. الاستجابة التفاعلية للأوامر اللحظية (On-Demand Finance Reports)
* يتكامل هذا الملف مع محلل الأوامر الذكي للبوت لتقديم خدمة الاستعلام الفوري.
* عند كتابة أمر `ميزانية` أو `استهلاك` عبر التيليجرام، يستيقظ هذا البروتوكول فوراً، ويسحب البيانات المالية والإحصائية من قاعدة البيانات، ويرسل لك تقريراً منسقاً ومفصلاً يحتوي على (حجم الأموال المستهلكة، عدد التوكنز المتبقية، وساعات عمل كرت الـ RTX)، دون أن يتسبب هذا الاستعلام اللحظي في تعطيل خط الإنتاج أو تجميد طابور الويب هوك.

### 3. الحوكمة المالية لنافذة الساعتين وطابور الويب هوك
* يتولى جدار الحماية المالي حظر وكيل التفاعل (`engagement_agent.md`) ومنعه من استدعاء النماذج اللغوية وصياغة الردود الذكية إذا كانت الميزانية اليومية للردود قد نفدت، مما يضمن التزام الوكيل التام بقيد نافذة الساعتين وحظر فورة المصاريف المستحدثة على مجتمع القناة.

### 4. بروتوكول التطهير ومسح الذاكرة المالي المشروط (النشر أو الإلغاء)
* خضوعاً للقاعدة الهندسية المتفق عليها، يرتبط جدار الحماية المالي ببروتوكول التطهير النهائي المشروط بالنهايتين المنطقيتين للمشروع:
  1. **بعد النشر الناجح فِعْلِيّاً:** فور تلقي إشعار الرفع الناجح من ملف `publishing_module.md` وإصدار الشهادة، يتم مسح كاش البيانات المالية المؤقتة للجلسة، وتصفير عدادات الاستهلاك الجزئي لتهيئة الخادم بشكل نظيف للفيديو القادم بعد 3 أيام تلافياً للتلوث السياقي للبيانات (Context Contamination).
  2. **بعد صُدورِ أَمْرِ الإِلْغَاءِ السَّامِي:** في حال قمت بإرسال أمر `الغاء` أو `رفض` للموضوع المقترح عبر البوت، يقوم جدار الحماية المالي فوراً بالمصادقة على تدمير ملفات الفيديو واللقطات الخام المعلقة في الهارد ديسك لمنع الهدر التخزيني وامتلاء الذاكرة، وتصفير الذاكرة الجلساتية ليعود السيرفر RTX إلى حالة الاستعداد النظيف 100%.

# وثيقة وكيل القانون والسياسات الدولي (eu_law_agent.md)

تحدد هذه الوثيقة البنية التشغيلية، المعايير القانونية، والآليات البرمجية الصارمة الموكلة إلى "وكيل القانون والسياسات الدولي" (EU Law & Platform Agent). يمثل هذا الوكيل بوابة الأمان القانونية والثانية في خط الدفاع النصي للنظام، ويتولى مهمة تدقيق النصوص والسيناريوهات والأوامر التوليدية (Prompts) لضمان توافقها التام مع قانون الذكاء الاصطناعي الأوروبي (AI Act) وسياسات النشر العالمية للمنصات قبل البدء في إنتاج الأصول المرئية.

---

## ⚖️ المعايير القانونية والرقابية الصارمة (مستوحاة من الملف القديم)

يعمل الوكيل كفلتر أمان لمنع حظر الحسابات أو تعرض النظام للمساءلة القانونية، ويقوم بمسح النص حرفياً للتحقق من خلوه من المخالفات التالية:

### 1. مطابقة قانون الذكاء الاصطناعي الدولي (AI Act Compliance)
* التحقق من حماية حقوق الملكية الفكرية، وتجنب نسخ أو اقتباس نصوص محمية بحقوق طبع ونشر دون تعديل جذري يضمن أصالة المحتوى المولد.
* التصفية الصارمة لكافة خطابات التضليل الرقمي (Disinformation)، أو الأخبار الزائفة، أو المحتويات العنيفة التي تحرض على الكراهية والتمييز بكافة أشكاله.

### 2. تدقيق سياسات النشر للمنصات (Anti-Shadowban Filter)
* الفحص الفوري للسيناريو عبر قاموس الكلمات الحساسة والمحظورة ديناميكياً على منصات (تيك توك، يوتيوب، وتويتر).
* رصد وتعديل العبارات المثيرة للجدل أو الكلمات التي تطلق خوارزميات الفلترة التلقائية للمنصات، لحماية القنوات من عقوبات الحظر الظلي أو إغلاق الحسابات المفاجئ.

---

## ⚙️ التحديث الهيكلي والربط مع المعمارية الجديدة (النقاط الخمس)

تمت إعادة تصميم المنطق البرمجي لهذا الوكيل لإلغاء بروتوكول الخروج القسري القديم (Hard Exit)، وتحويله إلى نظام تتابعي مرن يتكامل مع قاعدة البيانات المركزية وبوت التيليجرام لتفادي المشاكل التشغيلية مستقبلاً:

### 1. الفحص التتابعي الثاني (Pre-Render Pass)
* لا يستقبل هذا الوكيل النص إلا بعد نجاحه في اجتياز بوابة الفحص الشرعي الأولى (`islamic_compliance_agent.md`). يمرر النص فوراً عبر معايير الـ AI Act وفلاتر المنصات؛ وفي حال نجاحه، يصدر الوكيل وسم الموافقة (`Passed`) ليتحرك خط الإنتاج فورا نحو مرحلة توليد الأصول ورندرة كرت الـ RTX.

### 2. بروتوكول التغذية الراجعة وجدول الكاش المؤقت (Feedback Loop Cache)
* عند رصد أي مخالفة قانونية أو كلمة تسبب الحظر، يرفض الوكيل النص ويصيغ تقريراً قانونياً تفصيلياً (مثال: `تم الرفض لوجود الكلمة الحساسة [X] في السطر الخامس وسياقها يتسبب في حظر ظلي Shadowban على منصة تيك توك`).
* يرسل التقرير إلى الوكيل الإداري الأعلى، ليقوم برفع وتدوين المحاولة والنص وسبب الرفض داخل جدول قاعدة البيانات المؤقت `writer_session_cache` وتنبيه الكاتب لإعادة الصياغة.

### 3. التكامل مع بالوعة المحاولات الثلاث (3-Retry Sinkhole)
* يراقب الوكيل عداد المحاولات التشغيلية؛ فإذا تكرر رفضه للنص المعدل لثلاث مرات متتالية بسبب عدم قدرة الكاتب الآلي على تجاوز العقبات القانونية، يتوقف الوكيل عن استقبال أي مسودات إضافية، ويصدر أمر تجميد لموارد خادم الـ RTX، ثم يسلم ملف الطوارئ بالكامل للمدير ليرسله فورا لمقامكم السامي عبر بوت التيليجرام للتدخل البشري.

### 4. مسار تجاوز الفحص للاعتماد الملكي الصريح (Bypass Flag)
* في حال قمت أنت بكتابة السيناريو البديل يدوياً أو تعديله عبر التيليجرام وإرساله للنظام، يتلقى وكيل القانون الدولي إشارة حتمية بالإغلاق المؤقت (Bypass) لهذا الفيديو المحدد.
* يتم تمرير نصك السامي مباشرة إلى خط الإنتاج والتوليد دون خضوعه للفلاتر الآلية، باعتبار أن المحتوى قد نال الاعتماد والتدقيق البشري النهائي من قبلك.

### 5. بروتوكول التطهير ومسح الذاكرة السياقية المشروط (Post-Publish Session Flush)
* خضوعاً للقاعدة الهندسية الصارمة، يمنع هذا البروتوكول مسح أو حذف أي بيانات سياقية أثناء فترة معالجة خط الإنتاج.
* **التنفيذ الحتمي بعد النشر أو الإلغاء:** بمجرد صدور إشارة النشر النهائي الناجح من وحدة الرفع، أو عند استقبال أمر `الغاء` من قبلك عبر التيليجرام، يتم تفعيل أمر التطهير الشامل فوراً (Flush). عند هذه اللحظة بالذات، يتم تصفير الذاكرة السياقية (Context Window) للوكيل تماماً لحمايته من مشكلة التلوث السياقي، وتطهير جداول قاعدة البيانات المؤقتة ليكون السيرفر مستعداً بشكل نظيف 100% لموضوع جديد كلياً بعد 3 أيام.

        """

        suspicious_keywords = ["أثبتت الدراسات السرية", "معلومة صادمة لا يعرفها أحد", "خبر عاجل خطير"]

            if keyword in script_text:
                print(f"❌ [الوكيل الشرعي]: تم رفض النص محلياً لوجود عبارات مضللة: '{keyword}'")
                return {
                    "status": "FAILED",
                    "agent": "islamic_compliance_agent",
                    "reason": f"تم رصد صياغة إعلامية تثير الشائعات وغير مثبتة علمياً أو خبرياً: ({keyword})"
                }

        # [بند 7] حماية الاتصال الخارجي بحد أقصى 5 ثوانٍ لمنع تعليق خادم لابتوبك بالكامل
        try:
            headers = {

                    {"role": "user", "content": script_text}
                ],
                "response_format": {"type": "json_object"}
            }
            
            # محاكاة الاستجابة الآمنة في بيئة العمل المحلية صفرية التكلفة

            print("✅ [الوكيل الشرعي]: النص خالٍ من الكذب أو التضليل اللغوي ومطابق للقواعد المعرفية.")

                "status": "PASSED",
                "agent": "islamic_compliance_agent",
                "reason": "المحتوى متوافق تماماً مع قيم المصداقية والأمان اللغوي."
            }
            
        except Exception as e:

            return {
                "status": "FAILED",
                "agent": "islamic_compliance_agent",
                "reason": f"فشل اتصال الوكيل بقاعدة البيانات أو الـ API الخارجي: {e}"
            }

# ✍️ مواصفات تعلم وكيل كتابة المحتوى والسيناريو (AI_WRITER_LEARNING_SPEC.md)

## 🏗️ 1. سياق التشغيل والتشغيل المعزول (Sandbox Environment)
* **الأمان الصارم:** يعمل وكيل الكتابة كمستخدم مقيد الصلاحيات (Unprivileged User) ضمن بيئة اختبار معزولة (Sandbox) برمجياً لمنع حدوث أي حقن للأوامر (Prompt Injection) أو تعارض مفاجئ في المكتبات الخارجية لحماية السيرفر.

## 📈 2. آلية التعلم والربحية الدائمة (Continuous RPM Optimization)
يحتوي الوكيل على قاعدة بيانات تراكمية محلية يتم تحديثها تلقائياً وتسمى (`writer_knowledge_base`). يتعلم الكاتب برمجياً من كل جولة مراجعة أو رفض لضمان صياغة نصوص ترفع الأرباح تلقائياً، ويركز حتمياً على القواعد التسويقية التالية:
* **حماس أول 3 ثوانٍ:** صياغة افتتاحية قوية وجاذبة للمشاهد لمنع التمرير السريع (Hook).
* **رفع نسبة الـ CTR:** صياغة عناوين مثيرة وذكية تتوافق مع خوارزميات النشر وتجذب النقرات.
* **تجنب عبارات الهبوط:** شطب وتجنب الكلمات والعبارات المملة التي تقلل من نسبة الاحتفاظ بالجمهور (Audience Retention) لضمان بقاء المشاهد لأطول فترة ممكنة طمعاً في تضخيم الـ RPM.

## 🔄 3. بروتوكول استقبال تذاكر الإصلاح الموجهة (Granular Patching Response)
عند قيام مدير الإنتاج أو وكيل التدقيق والرقابة برفض جملة أو كلمة محددة، يلتزم الكاتب بالبروتوكول التالي:
1. **استقبال التذكرة المعزولة:** يستلم الكاتب تذكرة إصلاح موجهة للمقطع المصاب فقط (`segment_id`) تحتوي على: (النص المرفوض، التحليل القانوني والشرعي للمشكلة، والتوجيه التسويقي البديل لرفع الأرباح).
2. **إعادة الصياغة والتعلم الموضعي:** يقوم الكاتب بإعادة صياغة هذا المقطع المحدد فقط وحفظ القاعدة التسويقية والرقابية الجديدة في قاعدة بيانات التعلم المستدام الخاصة به، ثم يعيد المقطع للمدير لإصدار الموافقة النهائية دون هدر الـ Tokens في إعادة توليد النص كاملاً.

# 📊 مواصفات وكيل رصد الترند والنيش والمقترحات (AI_TREND_MANAGER.md)

## 🎯 1. النطاق والمسؤولية الحصرية (Trend & Niche Sovereignty)
يعمل هذا الوكيل كمحلل استثماري وباحث رئيسي للمنظومة. مهمته الحصرية تنحصر في دراسة السوق الرقمي، واقتناص الفرص الفيروسية (Viral Trends)، وقفل نطاق المحتوى بناءً على التوجيهات الدورية للمطور البشري لضمان تخصص القنوات ورفع الجدوى المالية.

## 📅 2. بوابة النيش الشهري الموجه (Niche Focus Control)
* **التوجيه النطاقي:** يمتثل الوكيل للأوامر الشهرية الصارية المباشرة الصادرة من المطور البشري (مثال: *"هذا الشهر ركز على مواضيع الطعام وفوائده"*).
* **آلية الحصر:** يقوم الوكيل بقفل خوارزميات ومحركات بحث الرصد لتعمل بنسبة 100% داخل النطاق الطبي، والغذائي، ونمط الحياة الصحي، ويُحظر عليه الخروج عن هذا النيش طوال الشهر التشغيلي لتثبيت تخصص المنصات أمام الجمهور والخوارزميات.

## 💰 3. نظام البرقيات المالية والتشاركية (ROI Projections & Trend Pivot)
* **إعداد المقترحات:** يقوم الوكيل بسحب الترندات المشتعلة وحساب الأرباح المتوقعة وعائد الـ RPM لكل لغة مستهدفة مقارنة بتكلفة الإنتاج التقديرية.
* **البرقية التشاركية المسبقة:** يُجبر الوكيل على إرسال تقرير مالي مسبق للمطور عبر التليجرام يتضمن (اسم الترند، الأرباح المتوقعة، وتكلفة إنتاجه) قبل اتخاذ أي خطوة إنتاجية.
* **إلغاء وتبديل المواضيع الخاسرة (Trend Pivoting):** إذا تبين للوكيل عبر الحسابات التقديرية أن موضوعاً ما خاسر مالياً ولن يجدي نفعاً، يمتلك الصلاحية التلقائية لإلغاء هذا الترند تماماً والتبديل اللحظي الفوري لموضوع آخر بديل يتمتع بنسب مشاهدة وأرباح متوقعة أعلى لحماية رأس مال المشروع.

# * بند 1: تهيئة وإنشاء قاعدة البيانات المحلية الخفيفة (SQLite) صفرية التكلفة السحابية.
# * بند 2: جدول التوثيق وسجلات الأمان الرقمية لإشارات GitHub Webhooks (platform_security).
# * بند 3: جدول طابور ومستودع استقبال تعليقات وإشارات المنصات الفوري (webhook_queue).
# * بند 4: جدول حفظ البصمات التشفيرية الحتمية للنصوص (script_hashes) عبر SHA-256 لمنع التكرار والحظر.
# * بند 5: جدول إصدار شهادات التوثيق الرقابي والمالي الشاملة للفيديوهات المنشورة (inspection_certificates).
# * بند 6: دالة إدارة وفحص أمان مفاتيح GitHub وحقن المتغيرات السرية (save_security_config).
# * بند 7: دالة إدخال إشارات الـ Webhook الواردة وتفعيل نظام الطابور الفوري (insert_webhook_request).
# * بند 8: دالة معالج الخلفية الصامت لاستدعاء وتحديث حالات الطلبات المعلقة (fetch_pending_and_update).
# * بند 9: دالة الفحص الاستباقي ومطابقة البصمة التشفيرية قبل الإنتاج لمنع الحظر الظلي (check_script_hash_exists).
# * بند 10: دالة توليد وحفظ شهادة التوثيق الرقابي الشاملة بعد نجاح دورة النشر (generate_inspection_certificate).

import sqlite3
import os
import json
from datetime import datetime

# اسم قاعدة البيانات المحلية الثابت للمنظومة
DB_NAME = "ai_trends.db"

# =====================================================================
# 🛠️ [بند 1] دالة تأسيس وبناء قاعدة البيانات والجداول الأساسية الكلية
# =====================================================================
def init_database_system():
    """
    تأسيس قاعدة البيانات وهيكلة الجداول الخمسة المعيارية لحفظ منطق العمل
    وحماية موارد السيرفر المحلي بشكل مستقل وصفري الكلفة السحابية.
    """
    print(f"⚙️ [{datetime.now().strftime('%Y-%m-%d %H:%M:%S')}]: جاري تهيئة وتأسيس جداول قاعدة البيانات المحلية...")
    conn = sqlite3.connect(DB_NAME)
    cursor = conn.cursor()
    
    # [بند 2] جدول التوثيق وسجلات الأمان الرقمية لإشارات GitHub Webhooks
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS platform_security (
            config_key TEXT PRIMARY KEY,
            config_value TEXT,
            last_updated TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        )
    ''')
    
    # [بند 3] جدول طابور ومستودع استقبال تعليقات وإشارات المنصات الفوري
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS webhook_queue (
            queue_id INTEGER PRIMARY KEY AUTOINCREMENT,
            platform_name TEXT NOT EXISTS,
            payload_data TEXT,
            status TEXT DEFAULT 'Pending',
            received_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
            processed_at TIMESTAMP
        )
    ''')
    
    # [بند 4] جدول حفظ البصمات التشفيرية الحتمية للنصوص عبر SHA-256 لمنع التكرار
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS script_hashes (
            hash_value TEXT PRIMARY KEY,
            associated_title TEXT,
            created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        )
    ''')
    
    # [بند 5] جدول إصدار شهادات التوثيق الرقابي والمالي الشاملة للنشر
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS inspection_certificates (
            video_id TEXT PRIMARY KEY,
            title TEXT,
            script_hash TEXT,
            islamic_status TEXT,
            eu_law_status TEXT,
            fact_check_status TEXT,
            finops_cost REAL,
            published_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
            FOREIGN KEY (script_hash) REFERENCES script_hashes(hash_value)
        )
    ''')
    
    conn.commit()
    conn.close()
    print("✅ تم بناء وهيكلة كافة جداول قاعدة البيانات بنجاح وصفريّة التكلفة السحابية!")

# =====================================================================
# 💾 الدوال التشغيلية والمتقدمة لإدارة وحفظ البيانات (سياق الملف الأصلي)
# =====================================================================

def save_security_config(key, value):
    """
    [بند 6] دالة إدارة وفحص أمان مفاتيح جيت هاب وحقن المتغيرات السرية محلياً.
    تضمن تحديث التوكنز والـ Secrets الحساسة دون قفل أو تعليق السيرفر.
    """
    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('''
            INSERT OR REPLACE INTO platform_security (config_key, config_value, last_updated)
            VALUES (?, ?, CURRENT_TIMESTAMP)
        ''', (key, value))
        conn.commit()
        conn.close()
        return True
    except sqlite3.Error as e:
        print(f"❌ خطأ برميجي في جدول الأمان: {e}")
        return False

def insert_webhook_request(platform, payload_text):
    """
    [بند 7] دالة إدخال إشارات الـ Webhook الواردة وتفعيل نظام الطابور الفوري.
    تأخذ البيانات وتحفظها بحالة 'Pending' فوراً للسماح للسيرفر بالرد بـ 200 OK.
    """
    try:
        # التحقق من صحة صياغة الجيسون قبل الإدخال لمنع تلويث الجدول
        if isinstance(payload_text, dict):
            payload_text = json.dumps(payload_text, ensure_ascii=False)
            
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('''
            INSERT INTO webhook_queue (platform_name, payload_data, status, received_at)
            VALUES (?, ?, 'Pending', CURRENT_TIMESTAMP)
        ''', (platform, payload_text))
        conn.commit()
        conn.close()
        return True
    except sqlite3.Error as e:
        print(f"❌ خطأ أثناء حقن الطلب في طابور الـ Webhook: {e}")
        return False

def fetch_pending_and_update(queue_id, new_status):
    """
    [بند 8] دالة معالج الخلفية الصامت لاستدعاء وتحديث حالات الطلبات المعلقة.
    يتم استدعاؤها عبر الـ Worker لتغيير الحالة إلى 'Processed' أو 'Expired'.
    """
    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('''
            UPDATE webhook_queue 
            SET status = ?, processed_at = CURRENT_TIMESTAMP
            WHERE queue_id = ?
        ''', (new_status, queue_id))
        conn.commit()
        conn.close()
        return True
    except sqlite3.Error as e:
        print(f"❌ خطأ أثناء تحديث أطوار طابور الـ Webhook: {e}")
        return False

def check_script_hash_exists(hash_hex, title_text):
    """
    [بند 9] دالة الفحص الاستباقي ومطابقة البصمة التشفيرية قبل الإنتاج لمنع الحظر الظلي.
    تفحص السجل التاريخي للبصمات لمنع هدر موارد كرت الشاشة وتكرار المحتوى.
    """
    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('SELECT 1 FROM script_hashes WHERE hash_value = ?', (hash_hex,))
        result = cursor.fetchone()
        
        if result:
            conn.close()
            return True  # البصمة مسجلة مسبقاً (محتوى مكرر خطير!)
            
        # إذا كانت البصمة جديدة، يتم حجزها برمجياً في الجدول لتأمين خط الإنتاج
        cursor.execute('''
            INSERT INTO script_hashes (hash_value, associated_title, created_at)
            VALUES (?, ?, CURRENT_TIMESTAMP)
        ''', (hash_hex, title_text))
        conn.commit()
        conn.close()
        return False
    except sqlite3.Error as e:
        print(f"❌ خطأ في مطابقة وفحص بصمة النص: {e}")
        return True

def generate_inspection_certificate(v_id, title, s_hash, islamic, eu_law, fact_check, cost):
    """
    [بند 10] دالة توليد وحفظ شهادة التوثيق الرقابي والمالي الشاملة بعد نجاح النشر.
    تؤمن مستند رقمي دائم يثبت جودة ونزاهة كل محتوى خرج من المنظومة.
    """
    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('''
            INSERT OR REPLACE INTO inspection_certificates 
            (video_id, title, script_hash, islamic_status, eu_law_status, fact_check_status, finops_cost, published_at)
            VALUES (?, ?, ?, ?, ?, ?, ?, CURRENT_TIMESTAMP)
        ''', (v_id, title, s_hash, islamic, eu_law, fact_check, cost))
        conn.commit()
        conn.close()
        print(f"📜 شهادة رقمية: تم إصدار شهادة التوثيق بنجاح للفيديو المرفوع رقم: {v_id}")
        return True
    except sqlite3.Error as e:
        print(f"❌ خطأ إداري أثناء إصدار شهادة الفحص: {e}")
        return False

# تشغيل التهيئة التلقائية لبناء البيئة والجداول فور استدعاء الملف
if __name__ == "__main__":
    init_database_system()
