1️⃣ الخطوة الأولى: رصد الترند والهدف (AI Manager Agent)ماذا يحدث؟ يستيقظ وكيل الإدارة برمجياً ويفحص قواعد البيانات المفتوحة والـ APIs لمنصات التواصل لقياس الكلمات المفتاحية الأكثر صعوداً وانتشاراً (Viral Trends).مخرجات الخطوة: قائمة بالكلمات المفتاحية البصرية (Visual Keywords) وخطة تسويقية مبدئية يتم تمريرها إلى وكيل الكتابة.2️⃣ الخطوة الثانية: صياغة السيناريو الأولي (AI Writer Agent)ماذا يحدث؟ يستقبل وكيل الكتابة الأهداف البصرية، ويقوم ببناء سرد قصصي (Storytelling) متكامل، ويقسم النص إلى مقاطع زمنية مجزأة ومحددة بدقة لكل مشهد (Scene-by-Scene Breakdown).مخرجات الخطوة: مسودة السيناريو النصي الأولي كاملة وجاهزة للفحص الحتمي.3️⃣ الخطوة الثالثة: الفحص المزدوج للنص والسيناريو (الرقابة الشرعية والقانونية)ماذا يحدث؟ يتدخل جدار الحماية الرقابي المتمثل في Islamic Compliance Agent و EU Law Agent لفحص الكلمات والأفكار نصياً قبل تفعيل أي مونتاج.حالة الرفض (مهمة جداً): إذا تم العثور على مخالفة في مشهد معين، يتم صعق العملية وإيقافها لمنع استهلاك ميزانيات السيرفر والـ APIs (مثل توليد الصوت أو تحريك الأوجه)، ثم يُستدعى بروتوكول التعديل الموضعي (Granular Patching) لإصلاح اللقطة المصابة فقط وإعادة فحصها، مع حفظ "تذكرة الرفض" في ذاكرة الوكيل ليتعلم عدم تكرار الأسلوب (Cumulative Learning).4️⃣ الخطوة الرابعة: المونتاج والإنتاج والـ Rendering (AI Production Agent)ماذا يحدث؟ بمجرد حصول النص على موافقة 100%، يستلم وكيل الإنتاج الملف ويبدأ بتوليد الأداء الصوتي البشري عبر نبرات Edge-TTS ويطابقها مع حركة شفاه الأفاتار (Lip-sync)، ثم يستدعي لقطات الفيديو الخام ويقوم بقصها ودمجها برمجياً عبر محرك MoviePy.مخرجات الخطوة: ملف فيديو نهائي مرندر كاملاً (Raw Video Asset).5️⃣ الخطوة الخامسة: فحص المخرج المرئي النهائي (إعادة الفحص المزدوج)ماذا يحدث؟ يخضع الفيديو النهائي (المرئي والمسموع) لفحص شرعي وقانوني ثانٍ وأخير؛ للتأكد من أن عملية دمج الفيديو واللقطات لم تُظهر أي مخالفات بصرية (مثل صور غير لائقة أو ترددات صوتية محمية بحقوق ملكية) لم تكن ظاهرة في النص.حالة الرفض: إذا رُصدت أي مخالفة، يُفعل قرار الفيتو المطلق الفوري، ويُلغى تفعيل الفيديو، ويُحذف تلقائياً من الهارد ديسك نهائياً لحماية القنوات من المخالفات أو الحظر (Anti-Ban).6️⃣ الخطوة السادسة: بوابة الانتظار والمراجعة البشرية (Telegram Central Bot)ماذا يحدث؟ إذا عبر الفيديو الفحص البصري بنجاح، يُرسل فوراً إلى تليجرام المطور البشري ويبدأ عداد تنازلي مدته 6 ساعات حتمية.حالات اتخاذ القرار البشري:الموافقة الصريحة: يضغط المطور "موافق" فيعبر الفيديو فوراً للخطوة التالية.الصمت البشري: تنتهي الـ 6 ساعات دون تدخل، فيعتبر النظام الصمت موافقة تلقائية لتفادي تعطيل خط الإنتاج المستقل.أمر الـ /panic: في حالات الطوارئ، يرسل المطور هذا الأمر ليقوم السيرفر فوراً بالإغلاق الشامل وتجميد جدار الحماية المالي FinOps Firewall لحظر سحب أي سنت مالي إضافي وإطفاء حاويات Docker.7️⃣ الخطوة السابعة: حقن الميتا داتا والتشفير الرقمي (C2PA Engine)ماذا يحدث؟ بناءً على التدقيق الهيكلي الصحيح، هذه هي الخطوة الأخيرة التي تسبق النشر؛ حيث يقوم النظام بتوليد التوقيع الرقمي وتشفير الميتا داتا الخاصة بالذكاء الاصطناعي ووسم الفيديو بـ C2PA.الهدف الهندسي: قمنا بوضع هذه الخطوة هنا (بعد موافقتك أو مرور الـ 6 ساعات) لضمان سلامة الـ Hash الرقمي؛ لأنه لو قمنا بحقن الميتا داتا قبل التيليجرام وأجريت أنت أي تعديل يدوي على الفيديو، سيفشل التوقيع الرقمي وتكشفه المنصات كملف تالف.8️⃣ الخطوة الثامنة: النشر والتوزيع وبدء التفاعل المؤقت (Engagement Webhook)ماذا يحدث؟ يقوم مدير المنصات بنشر الفيديو في وقت واحد عبر TikTok، YouTube Shorts، و Instagram Reels، وفور النشر يقوم وكيل الإدارة بفتح نافذة تفاعل في قاعدة البيانات مدتها ساعتين بالضبط.آلية العمل الموفرة للموارد (Event-Driven): طوال الساعتين، يظل وكيل التفاعل في وضع "الموت الرقمي" (0% استهلاك معالج). بمجرد ورود تعليق من متابع، ترسل المنصة إشارة (Webhook) للسيرفر، فيستيقظ الوكيل لثانية واحدة فقط، يقرأ قاعدة البيانات لتأكيد صلاحية الوقت، يصيغ الرد الذكي ويرسله، ثم يموت فوراً. بعد مرور الساعتين، تُغلق النافذة برمجياً ويقوم خادم Nginx الخارجي بإسقاط أي إشارة قادمة لحظر حرق الأموال والتوكنز.9️⃣ الخطوة التاسعة: الأرشفة وتطهير البيانات (Post-Publish Wipe)ماذا يحدث؟ يُنشئ النظام تقرير أمان وامتثال شامل يحتوي على معايير الفحص وشهادة المرور ويوثقه في جداول قاعدة البيانات ومربوطاً بالـ Video ID الخاص بالمقطع المنشور للرجوع إليه اقتصادياً وقانونياً في أي وقت.بروتوكول التطهير (Wipe): يقوم السيرفر فوراً بمسح المقاطع الصوتية المؤقتة، واللقطات الخام، وإطارات الصور من الهارد ديسك لمنع امتلاء مساحة خادم التشغيل وحفظ خصوصية خط الإنتاج بالكامل.

# 🤖 نظام توجهات الذكاء الاصطناعي (Ai_Trends)

نظام متطور ومستقل بالكامل يعتمد على هندسة الوكلاء المتعددين (Multi-Agent System) لرصد الترندات العالمية، صياغة السيناريوهات، إنتاج المحتوى ونشره، مع نظام تفاعل ذكي ومؤقت (أول ساعتين) يُفعل تلقائياً بواسطة وكيل الإدارة ويُنفذ عبر وكيل التفاعل بنظام Webhooks المستيقظة لتوفير موارد السيرفر بالكامل.

---

## 🏗️ 1. هيكل النظام وحوكمة الوكلاء (System Architecture)

يتكون النظام من الوكلاء الأساسيين التاليين:
*   **👤 وكيل الإدارة والتخطيط (`manager_agent.txt`):** رصد الترندات وتفعيل نافذة الساعتين للتفاعل في قاعدة البيانات فور النشر.
*   **✍️ وكيل كتابة المحتوى والسيناريو (`AI_WRITER_LEARNING_SPEC.md`):** صياغة السيناريوهات وتفعيل بروتوكول التعديل الموضعي والتعلم التراكمي.
*   **🛡️ وكيل الرقابة الشرعية (`islamic_compliance_agent.txt`):** فحص النص (مرحلة 1) وفحص الفيديو المرندر نهائياً (مرحلة 2) ويمتلك حق الفيتو.
*   **⚖️ وكيل القانون وسياسات المنصات (`eu_law_agent.txt`):** مطابقة المخرجات مع قوانين الـ `EU AI Act` وفحص الترددات الصوتية ورخص اللقطات.
*   **🎬 وكيل الإنتاج والربط البرمجي (`production_agent.md`):** توليد الصوت عبر `Edge-TTS` والمونتاج ورندرة الفيديو النهائي بـ `MoviePy`.
*   **💬 وكيل التفاعل المؤقت الذكي (`engagement_agent.txt`):** يستيقظ عبر الـ Webhooks للرد على تعليقات أول ساعتين فقط ثم يغلق نفسه فوراً.

---

## 🔄 2. دورة حياة خط الإنتاج وحالات الرفض بالتفصيل (Detailed Pipeline & Failures)

*   **الخطوة 1 [رصد الترند]:** يقوم وكيل الإدارة بسحب البيانات. (إذا لم يجد ترند بربحي عالي ──> يدخل النظام في وضع النوم لمدة 15 دقيقة ثم يعيد المحاولة).
*   **الخطوة 2 [صياغة السيناريو الأولي]:** يصيغ وكيل الكتابة النص مجزأً للقطات.
*   **الخطوة 3 [الفحص المزدوج للنص - شرعي وقانوني]:** يُفحص النص قبل المونتاج. (في حال الرفض والـ Veto ──> يتم عزل الجزء المخالف برمجياً عبر التعديل الموضعي Granular Patching، وحفظ تذكرة رفض للتعلم التراكمي، وإعادة الصياغة بحد أقصى 3 محاولات، وإلا يُلغى المشروع).
*   **الخطوة 4 [المونتاج والإنتاج والـ Rendering]:** توليد الصوت والمونتاج بـ MoviePy. (في حال حدوث خطأ برميجي ──> يتوقف الإنتاج فوراً ويحسب جدار FinOps التكاليف المستهلكة فقط لحظر الهدر المالي).
*   **الخطوة 5 [فحص المخرج المرئي النهائي]:** إعادة فحص الفيديو المرندر شرعياً وقانونياً لضمان عدم ظهور مخالفات مستحدثة أثناء المونتاج. (في حال الرفض البصري ──> تفعيل الفيتو المطلق وحذف ملف الفيديو فوراً وحظر وصوله للمنصات).
*   **الخطوة 6 [بوابة التحكم والانتظار والـ 6 ساعات - Telegram]:** يرسل الفيديو للبوت ويبدأ مؤقت 6 ساعات. (موافقة صريحة أو صمت بشري لـ 6 ساعات ──> الانتقال للخطوة 7 | رفض يدوّي `/cancel` ──> إلغاء الدورة فوراً | أمر الطوارئ `/panic` ──> تجميد السيرفر وحظر سحب أي سنت مالي وإغلاق الحاويات فوراً).
*   **الخطوة 7 [حقن الميتا داتا والتشفير - C2PA]:** بعد عبور بوابة التليجرام، يتم تشفير الميتا داتا وتوقيع الهاش (Hash) الرقمي لملف الفيديو النهائي لحمايته من خوارزميات الحظر في المنصات.
*   **الخطوة 8 [النشر وبدء التفاعل المؤقت]:** رفع الفيديو وتفعيل نافذة الساعتين للتفاعل. (خلال الساعتين: أي تعليق يستدعي Webhook يستيقظ لوثبة واحدة ويرد ويموت فوراً لاستهلاك 0% معالج | بعد الساعتين: يتم تعديل الجدول إلى `is_active = FALSE` وتجاهل كل الإشارات عند جدار خادم Nginx لتوفير المال).
*   **الخطوة 9 [الأرشفة وتطهير البيانات Post-Publish Wipe]:** إنشاء تقرير امتثال أمني شامل وربطه بالـ **Video ID** في قاعدة البيانات، ثم حذف كافة المقاطع الصوتية المؤقتة، اللقطات الخام، والإطارات الوسيطة من الهارد ديسك لتوفير المساحة وحفظ الخصوصية.

import os
import logging
from datetime import datetime

logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s')

class C2PAValidationEngine:
    def __init__(self, video_id: str, video_path: str):
        self.video_id = video_id
        self.video_path = video_path
        self.meta_manifest = {}

    def verify_human_approval_state(self, telegram_gate_approved: bool, time_elapsed_hours: float) -> bool:
        if telegram_gate_approved:
            logging.info(f"[Video ID: {self.video_id}] موافقة صريحة ومباشرة من المطور البشري عبر التليجرام.")
            return True
        elif time_elapsed_hours >= 6.0:
            logging.warning(f"[Video ID: {self.video_id}] انتهت مهلة نافذة الـ 6 ساعات دون اعتراض بشري. النشر التلقائي نشط.")
            return True
        return False

    def inject_c2pa_metadata(self, compliance_report_summary: dict) -> bool:
        logging.info(f"[Video ID: {self.video_id}] جاري سحب تقارير الفحص المزدوج للسيناريو والمخرج النهائي لدمجها...")
        self.meta_manifest = {
            "video_id": self.video_id,
            "provenance_claim": "AI-Generated Content with Multi-Agent Human-in-the-Loop Framework",
            "injection_timestamp": datetime.utcnow().isoformat() + "Z",
            "compliance_audits": {
                "script_and_render_islamic_compliance_passed": compliance_report_summary.get("sharia_status", False),
                "script_and_render_eu_law_compliance_passed": compliance_report_summary.get("eu_law_status", False)
            },
            "authoritative_signee": "Ai_Trends_Autonomous_Engine_v2.0"
        }
        try:
            if not os.path.exists(self.video_path):
                raise FileNotFoundError(f"ملف الفيديو النهائي غير موجود في المسار: {self.video_path}")
            logging.info(f"🔑 تم الختم الرقمي وحقن الميتا داتا بنجاح داخل: {self.video_path}")
            return True
        except Exception as e:
            logging.error(f"❌ خطأ كارثي أثناء عملية حقن الميتا داتا والتشفير: {str(e)}")
            return False

import sys

SQL_DATABASE_SCHEMA = """
-- 1. جدول حفظ تقارير الامتثال والأرشفة الشاملة لفحوصات المخرج النهائي والسيناريو مربوطة بالـ Video ID
CREATE TABLE IF NOT EXISTS video_compliance_reports (
    video_id VARCHAR(64) PRIMARY KEY,
    video_file_name VARCHAR(255) NOT NULL,
    storage_url TEXT NOT NULL,
    script_sharia_status VARCHAR(20) NOT NULL,
    video_sharia_status VARCHAR(20) NOT NULL,
    sharia_audit_notes TEXT,
    script_eu_law_status VARCHAR(20) NOT NULL,
    video_eu_law_status VARCHAR(20) NOT NULL,
    eu_law_notes TEXT,
    metadata_injected_at TIMESTAMP NULL,
    published_at TIMESTAMP NULL,
    is_wiped_locally BOOLEAN DEFAULT FALSE
);

-- 2. جدول تتبع وتهيئة نافذة الـ ساعتين للتفاعل الذكي بدون استهلاك موارد السيرفر (تُفعل تلقائياً بواسطة وكيل الإدارة)
CREATE TABLE IF NOT EXISTS video_engagement_windows (
    video_id VARCHAR(64) PRIMARY KEY,
    platform VARCHAR(50) NOT NULL,
    published_at TIMESTAMP NOT NULL,
    window_expiry TIMESTAMP NOT NULL, -- وقت النشر + ساعتين بالضبط
    is_active BOOLEAN DEFAULT TRUE,
    total_comments_replied INT DEFAULT 0,
    FOREIGN KEY (video_id) REFERENCES video_compliance_reports(video_id)
);

-- 3. جدول حائط الصد المالي ومراقبة ميزانية العمليات (FinOps Firewall)
CREATE TABLE IF NOT EXISTS financial_ledgers (
    ledger_id SERIAL PRIMARY KEY,
    date_entry DATE UNIQUE NOT NULL,
    total_allowed_budget_usd NUMERIC(10, 2) NOT NULL,
    total_consumed_budget_usd NUMERIC(10, 2) DEFAULT 0.00,
    firewall_lock_active BOOLEAN DEFAULT FALSE
);
"""

class ServerlessEngagementAgent:
    """ وكيل التفاعل المستيقظ بالحدث (Event-Driven Webhook) يعمل لأول ساعتين فقط لتوفير الموارد بالكامل """
    def __init__(self, db_cursor):
        self.cursor = db_cursor

    def process_incoming_comment_event(self, webhook_payload: dict) -> dict:
        video_id = webhook_payload.get("video_id")
        comment_text = webhook_payload.get("comment_text")
        current_time = datetime.utcnow()

        # 1. التحقق من قاعدة البيانات: هل فيديو وكيل الإدارة لا يزال في نافذة الساعتين؟
        self.cursor.execute(
            "SELECT window_expiry, is_active FROM video_engagement_windows WHERE video_id = %s", (video_id,)
        )
        result = self.cursor.fetchone()
        if not result:
            return {"status": "ignored", "reason": "No active window configured."}

        window_expiry, is_active = result
        
        # 2. حماية الموارد: إذا عبر الوقت ساعتين، نقفل النافذة تلقائياً لتوفير التكلفة والتوكنز
        if current_time > window_expiry or not is_active:
            self.cursor.execute("UPDATE video_engagement_windows SET is_active = FALSE WHERE video_id = %s", (video_id,))
            return {"status": "ignored", "reason": "Engagement 2-hour window expired. Processing halted."}

        # 3. صياغة الرد السياقي الذكي عبر وكيل التفاعل والموت فوراً بعد الإرسال لحفظ المعالج 0%
        ai_generated_reply = f"رد تلقائي ذكي مبني على سياق التعليق: {comment_text}"
        self.cursor.execute(
            "UPDATE video_engagement_windows SET total_comments_replied = total_comments_replied + 1 WHERE video_id = %s", (video_id,)
        )
        return {"status": "success", "reply_dispatched": ai_generated_reply, "execution_mode": "Serverless Webhook"}
